# Firewalls

`Firewalls` определяют область, в которой применяется логика аутентификации.
Определяется через `pattern`/`host`,`methods`. Во всех роутах совпадающих с условием будет запускаться процесс аутентификации независимо от `Access Control`.

`Symfony` перебирает список файрволов в `security.yaml` сверху вниз и будет обработан первый совпавший по условиям.

Параметры `firewalls`:
* `pattern` - Регулярное выражение для URL. Если не указан, подходит любой URL
* `host` - Ограничение по домену
* `methods` - Список HTTP-методов
* `security` - Если `false`, Symfony полностью отключит систему безопасности для этого пути
* `stateless` - Если `true`, Symfony не будет создавать сессию и сохранять пользователя в ней, для API
* `provider` - Указывает, какой user provider использовать для поиска пользователей в этом файрволе
* `lazy` - Если `true`, Symfony откладывает момент вызова аутентификатора до тех пор, пока данные о пользователе не понадобятся в коде
* `entry_point` - Сервис/роут, который решает, что делать с неавторизованным пользователем - редирект на /login или возврат JSON 401

`providers` определяет конфигурацию загрузчиков данных юзера для аутентификатора.
Обычно это doctrine entity или `chain` - цепочка провайдеров которые будут вызваны при загрузке пользователя
`property` это поле, которое будет использоваться для загрузки пользователя, его значение указывается в `UserBadge`.

```yaml
    providers:
      chain_user_provider:
        chain:
          providers: [ admin_user_provider, user_provider ]
      chain_provider:
        chain:
          providers: [ api_client_provider, admin_user_provider, user_provider ]
      user_provider:
        entity:
          class: App\Entity\User
          property: email
      admin_user_provider:
        entity:
          class: App\Entity\Admin
          property: email
      api_client_provider:
        entity:
          class: App\Entity\ApiClient
          property: clientId

    firewalls:
      dev:
        pattern: ^/(_profiler|_wdt|assets|build)/
        security: false

      admin:
        pattern: ^/admin/
        lazy: true
        provider: admin_user_provider
        form_login: # стандартный аутентификатор для формы логина
          login_path: admin_login  # роут для формы логина
          check_path: admin_login  # роут для обработки POST запроса с кредами 
          enable_csrf: true
        logout:
          path: admin_logout

      api:
        pattern: ^/api/
        lazy: true
        stateless: true
        provider: chain_provider
        access_token: # стандартный аутентификатор токенов
          token_handler: App\Security\AccessTokenHandler # обязательно нужно создать token_handler, который будет загружать данные токена
          token_extractors: # можно добавить несколько token extractor
            - 'header'                               # стандартный Authorization: Bearer
            - 'App\Security\CookiesTokenExtractor'   # можно добавить свой кастомный
        custom_authenticators:                  # можно добавить свои кастомные аутентификаторы
          - App\Security\ApiKeyAuthenticator

      web:
        provider: chain_user_provider
        form_login:
          login_path: web_login
          check_path: web_login
          enable_csrf: true
        logout:
          path: web_logout
```
