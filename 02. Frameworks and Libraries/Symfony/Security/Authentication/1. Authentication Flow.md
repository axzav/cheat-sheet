# Authentication Flow

Flow аутентификации `Symfony` выглядит так:
```text
kernel.request
   ↓
Firewall
   ↓
ContextListener (если не stateless: попытка восстановить Token из Session)
   ↓
AuthenticatorManagerListener 
   ↓
AuthenticatorManager::authenticateRequest()
   ↓
   ├─ Loop Authenticator::supports()
   └─ Authenticator::authenticate() → возвращает Passport
        ↓
    CheckPassportEvent (UserChecker, PasswordHasher, Badge resolving)
        ↓
   SUCCESS? 
   ├─ YES: 
   │  ├─ Authenticator::createToken()
   │  ├─ TokenStorage::setToken()
   │  ├─ Authenticator::onAuthenticationSuccess()
   │  └─ Return Response OR Continue to Controller
   └─ NO:
      ├─ Authenticator::onAuthenticationFailure()
      └─ Return Response (401/Redirect) OR Throw Exception OR Continue to Controller
```

## FirewallListener

Проверяет, подпадает ли текущий запрос под какой-то из зарегистрированных `firewalls`.

## ContextListener

В случае если `firewall` не `stateless`, то `ContextListener` пытается загрузить токен из сессии. В случае успеха запрос проходит дальше без вызова `AuthenticatorManager`.

## AuthenticatorManager

Основная логика аутентификации тут. `AuthenticatorManager` проходит по **ВСЕМ** зарегистрированным для `firewalls` аутентификаторам и вызывает `Authenticator::supports()`.

Вызывается `Authenticator::authenticate()`. Он возвращает объект `Passport`.
Это временный объект-контейнер, его задача — собрать все данные, необходимые для проверки пользователя.
`Passport` содержит в себе `Badges`, обязательный `UserBadge` и другие дополнительные в зависимости от `Passport` и других условий.

После создания `Passport` создается ивент `CheckPassportEvent`. Слушатели:
* `UserProviderListener` - устанавливает провайдер для загрузки пользователя из конфигурации `firewalls`;
* `UserCheckerListener` - загружает пользователя через провайдер (`Passport::getUser()` → `UserBadge::getUser()`);
* `CheckCredentialsListener` - если есть `PasswordCredentials|CustomCredentials` вызывает проверку кредов, тут вызывается `PasswordHasher`.

Если все `Badges` `isResolved`, тогда вызывается `Authenticator::createToken()` и токен сохраняется в `TokenStorage`.

Если все прошло успешно, то вызывается `Authenticator::onAuthenticationSuccess()`.
В случае исключения или ошибки на любом этапе вызывается `Authenticator::onAuthenticationFailure()`.

В зависимости от логики в этих методах исполнение кода может быть продолжено (даже для `onAuthenticationFailure`) или может быть возвращен объект респонза, например редирект.
Для API в основном это будет `null` (продолжить выполнение кода, Access Control решит, давать ли доступ), логин формы будут возвращать редирект.
