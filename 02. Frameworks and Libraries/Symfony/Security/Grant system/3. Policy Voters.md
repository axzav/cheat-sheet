# Policy Voters

Обычно для воутеров применяется схема создания воутера на ресурс:
```text
AccountVoter
    → ACCOUNT_VIEW
    → ACCOUNT_EDIT
    → ACCOUNT_DELETE
OrganizationVoter
    ...
CampaignVoter
    ...
```

В таком случае бизнес-логика обычно разрастается внутри воутра + каждый security check вызывает все воутеры в приложении.
Паттерн `Policy Voters` позволяет отдельно бизнес логику системы доступа (Domain Level) от кода `Voter` (Infra level). 
Остается только один `Voter`, который становится универсальным и выполняет только роль роутера:

```text
Security/
 ├ Policy/
 │   ├ OrganizationPolicy
 │   ├ AccountPolicy
```

```php
class AccountPolicy
{
    public function view(User $user, Account $account)
    {
        ...
    }

    public function edit(User $user, Account $account)
    {
        ...
    }
}
```

```php
class PolicyVoter extends Voter
{
    protected function voteOnAttribute(
        string $attribute,
        $subject,
        TokenInterface $token
    ) {
        return $this->policyResolver
            ->resolve($subject)
            ->{$attribute}($token->getUser(), $subject);
    }
}
```
