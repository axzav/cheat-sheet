# Other Index Types

Beyond B-tree and Hash indexes, databases support various specialized index types for different use cases.

## GiST (Generalized Search Tree) - PostgreSQL

Generalized index structure supporting various data types and operations.

### Use Cases
- Full-text search
- Geometric data (PostGIS)
- Array operations
- Custom data types

### Example
```sql
CREATE INDEX idx_location ON places USING GIST (location);
-- location is a PostGIS geometry type
```

## GIN (Generalized Inverted Index) - PostgreSQL

Optimized for cases where multiple values map to one row (arrays, full-text search).

### Use Cases
- Full-text search
- Array containment queries
- JSON/JSONB queries
- hstore (key-value pairs)

### Example
```sql
-- Full-text search
CREATE INDEX idx_content ON articles USING GIN (to_tsvector('english', content));

-- Array queries
CREATE INDEX idx_tags ON posts USING GIN (tags);

-- JSON queries
CREATE INDEX idx_data ON documents USING GIN (data);
```

## BRIN (Block Range Index) - PostgreSQL

Very compact index storing min/max values per block range.

### Characteristics
- Extremely small size
- Fast to build
- Good for large, naturally ordered tables
- Less precise than B-tree

### Use Cases
- Time-series data
- Monotonically increasing values
- Very large tables where B-tree is too large

### Example
```sql
CREATE INDEX idx_timestamp ON logs USING BRIN (timestamp);
```

## SP-GiST (Space-Partitioned GiST) - PostgreSQL

Supports non-balanced disk-based data structures.

### Use Cases
- Non-balanced trees
- Tries (prefix matching)
- Quad-trees
- k-d trees

### Example
```sql
CREATE INDEX idx_text ON words USING SP_GIST (word);
```

## Full-Text Search Indexes

### PostgreSQL
```sql
-- Create tsvector column
ALTER TABLE articles ADD COLUMN content_vector tsvector;
UPDATE articles SET content_vector = to_tsvector('english', content);

-- Create GIN index
CREATE INDEX idx_content_vector ON articles USING GIN (content_vector);

-- Search
SELECT * FROM articles 
WHERE content_vector @@ to_tsquery('english', 'database & performance');
```

### MySQL Full-Text Index
```sql
-- Create full-text index
CREATE FULLTEXT INDEX idx_content ON articles (content);

-- Search
SELECT * FROM articles 
WHERE MATCH(content) AGAINST('database performance' IN NATURAL LANGUAGE MODE);
```

## Spatial Indexes

### PostGIS (PostgreSQL)
```sql
-- Create spatial index
CREATE INDEX idx_geom ON places USING GIST (geom);

-- Spatial queries
SELECT * FROM places 
WHERE ST_DWithin(geom, ST_MakePoint(lon, lat), 1000);
```

### MySQL Spatial Index
```sql
CREATE SPATIAL INDEX idx_location ON places (location);
```

## Bitmap Indexes

Store bitmap for each distinct value.

### Characteristics
- Efficient for low-cardinality columns
- Good for read-heavy workloads
- Not suitable for frequently updated data

### Use Cases
- Data warehousing
- OLAP systems
- Low-cardinality columns (gender, status, etc.)

## Covering Indexes

Index that contains all columns needed for a query.

### PostgreSQL
```sql
-- Index includes all queried columns
CREATE INDEX idx_covering ON orders (user_id) INCLUDE (order_date, total);
```

### MySQL
```sql
-- Composite index covering all columns
CREATE INDEX idx_covering ON orders (user_id, order_date, total);
```

## Partial Indexes

Index only a subset of rows based on condition.

### PostgreSQL
```sql
-- Index only active users
CREATE INDEX idx_active_users ON users (email) WHERE status = 'active';
```

### MySQL
```sql
-- Functional index (MySQL 8.0+)
CREATE INDEX idx_active_users ON users ((email)) WHERE status = 'active';
```

## Expression Indexes

Index on computed/expression values.

### PostgreSQL
```sql
-- Index on lowercased email
CREATE INDEX idx_email_lower ON users (LOWER(email));

-- Index on date extraction
CREATE INDEX idx_year ON orders (EXTRACT(YEAR FROM order_date));
```

### MySQL
```sql
-- Functional index (MySQL 8.0+)
CREATE INDEX idx_email_lower ON users ((LOWER(email)));
```

## Unique Indexes

Enforce uniqueness constraint.

```sql
-- PostgreSQL and MySQL
CREATE UNIQUE INDEX idx_email_unique ON users (email);
```

## Composite Indexes

Index on multiple columns.

```sql
CREATE INDEX idx_composite ON orders (user_id, order_date, status);
```

### Column Order Matters
- Leftmost prefix rule
- Most selective columns first
- Frequently queried columns first

## Index Selection Guidelines

1. **B-tree**: Default choice, supports range queries
2. **Hash**: Equality queries only, very fast
3. **GIN**: Arrays, full-text, JSON
4. **GiST**: Geometric data, custom types
5. **BRIN**: Large ordered tables
6. **Full-Text**: Text search requirements
7. **Spatial**: Geographic/geometric data

## Index Maintenance

```sql
-- Rebuild index
REINDEX INDEX index_name;  -- PostgreSQL
ALTER TABLE table_name DROP INDEX index_name, ADD INDEX index_name (...);  -- MySQL

-- Analyze index usage
ANALYZE table_name;  -- PostgreSQL
ANALYZE TABLE table_name;  -- MySQL

-- Check index size
SELECT pg_size_pretty(pg_relation_size('index_name'));  -- PostgreSQL
SHOW TABLE STATUS LIKE 'table_name';  -- MySQL
```
