# Other Index Types

Помимо B-tree и Hash indexes, базы данных поддерживают различные специализированные типы индексов для разных случаев использования.

## GiST (Generalized Search Tree) - PostgreSQL

Обобщенная структура индекса, поддерживающая различные типы данных и операции.

### Случаи использования
- Full-text search
- Геометрические данные (PostGIS)
- Операции с массивами
- Пользовательские типы данных

### Пример
```sql
CREATE INDEX idx_location ON places USING GIST (location);
-- location - это тип geometry PostGIS
```

## GIN (Generalized Inverted Index) - PostgreSQL

Оптимизирован для случаев, когда несколько значений сопоставляются с одной строкой (массивы, full-text search).

### Случаи использования
- Full-text search
- Запросы на вхождение в массив
- Запросы по JSON/JSONB
- hstore (пары ключ-значение)

### Пример
```sql
-- Full-text search
CREATE INDEX idx_content ON articles USING GIN (to_tsvector('english', content));

-- Запросы по массивам
CREATE INDEX idx_tags ON posts USING GIN (tags);

-- Запросы по JSON
CREATE INDEX idx_data ON documents USING GIN (data);
```

## BRIN (Block Range Index) - PostgreSQL

Очень компактный индекс, хранящий минимальные/максимальные значения для каждого диапазона блоков.

### Характеристики
- Очень маленький размер
- Быстрое создание
- Хорошо подходит для больших, естественно упорядоченных таблиц
- Менее точный, чем B-tree

### Случаи использования
- Данные временных рядов
- Монотонно возрастающие значения
- Очень большие таблицы, где B-tree слишком большой

### Пример
```sql
CREATE INDEX idx_timestamp ON logs USING BRIN (timestamp);
```

## SP-GiST (Space-Partitioned GiST) - PostgreSQL

Поддерживает несбалансированные структуры данных на диске.

### Случаи использования
- Несбалансированные деревья
- Tries (поиск по префиксу)
- Quad-trees
- k-d trees

### Пример
```sql
CREATE INDEX idx_text ON words USING SP_GIST (word);
```

## Full-Text Search Indexes

### PostgreSQL
```sql
-- Создать столбец tsvector
ALTER TABLE articles ADD COLUMN content_vector tsvector;
UPDATE articles SET content_vector = to_tsvector('english', content);

-- Создать GIN индекс
CREATE INDEX idx_content_vector ON articles USING GIN (content_vector);

-- Поиск
SELECT * FROM articles 
WHERE content_vector @@ to_tsquery('english', 'database & performance');
```

### MySQL Full-Text Index
```sql
-- Создать full-text индекс
CREATE FULLTEXT INDEX idx_content ON articles (content);

-- Поиск
SELECT * FROM articles 
WHERE MATCH(content) AGAINST('database performance' IN NATURAL LANGUAGE MODE);
```

## Spatial Indexes

### PostGIS (PostgreSQL)
```sql
-- Создать spatial индекс
CREATE INDEX idx_geom ON places USING GIST (geom);

-- Spatial запросы
SELECT * FROM places 
WHERE ST_DWithin(geom, ST_MakePoint(lon, lat), 1000);
```

### MySQL Spatial Index
```sql
CREATE SPATIAL INDEX idx_location ON places (location);
```

## Bitmap Indexes

Хранят bitmap для каждого уникального значения.

### Характеристики
- Эффективны для столбцов с низкой кардинальностью
- Хорошо подходят для нагрузок с преобладанием чтения
- Не подходят для часто обновляемых данных

### Случаи использования
- Data warehousing
- OLAP системы
- Столбцы с низкой кардинальностью (пол, статус и т.д.)

## Covering Indexes

Индекс, который содержит все столбцы, необходимые для запроса.

### PostgreSQL
```sql
-- Индекс включает все запрашиваемые столбцы
CREATE INDEX idx_covering ON orders (user_id) INCLUDE (order_date, total);
```

### MySQL
```sql
-- Составной индекс, покрывающий все столбцы
CREATE INDEX idx_covering ON orders (user_id, order_date, total);
```

## Partial Indexes

Индексируют только подмножество строк на основе условия.

### PostgreSQL
```sql
-- Индексировать только активных пользователей
CREATE INDEX idx_active_users ON users (email) WHERE status = 'active';
```

### MySQL
```sql
-- Functional index (MySQL 8.0+)
CREATE INDEX idx_active_users ON users ((email)) WHERE status = 'active';
```

## Expression Indexes

Индекс на вычисляемых значениях/выражениях.

### PostgreSQL
```sql
-- Индекс на email в нижнем регистре
CREATE INDEX idx_email_lower ON users (LOWER(email));

-- Индекс на извлечение года
CREATE INDEX idx_year ON orders (EXTRACT(YEAR FROM order_date));
```

### MySQL
```sql
-- Functional index (MySQL 8.0+)
CREATE INDEX idx_email_lower ON users ((LOWER(email)));
```

## Unique Indexes

Обеспечивают ограничение уникальности.

```sql
-- PostgreSQL и MySQL
CREATE UNIQUE INDEX idx_email_unique ON users (email);
```

## Composite Indexes

Индекс на нескольких столбцах.

```sql
CREATE INDEX idx_composite ON orders (user_id, order_date, status);
```

### Порядок столбцов важен
- Правило leftmost prefix
- Наиболее селективные столбцы первыми
- Часто запрашиваемые столбцы первыми

## Рекомендации по выбору индекса

1. **B-tree**: Выбор по умолчанию, поддерживает запросы по диапазону
2. **Hash**: Только запросы на равенство, очень быстрый
3. **GIN**: Массивы, full-text, JSON
4. **GiST**: Геометрические данные, пользовательские типы
5. **BRIN**: Большие упорядоченные таблицы
6. **Full-Text**: Требования к поиску по тексту
7. **Spatial**: Географические/геометрические данные

## Обслуживание индексов

```sql
-- Перестроить индекс
REINDEX INDEX index_name;  -- PostgreSQL
ALTER TABLE table_name DROP INDEX index_name, ADD INDEX index_name (...);  -- MySQL

-- Анализировать использование индекса
ANALYZE table_name;  -- PostgreSQL
ANALYZE TABLE table_name;  -- MySQL

-- Проверить размер индекса
SELECT pg_size_pretty(pg_relation_size('index_name'));  -- PostgreSQL
SHOW TABLE STATUS LIKE 'table_name';  -- MySQL
```
