Индексы в базах данных используются для ускорения процесса поиска и извлечения данных. Эти инструменты особенно важны в условиях больших объемов данных и сложных запросов. Могут быть сравнены с оглавлением книги: вместо того, чтобы просматривать всю книгу (или всю таблицу данных), система может обратиться к индексу, чтобы быстро найти нужную информацию.

## Основные случаи использования

### Поиск по ключевым столбцам

Если запросы часто включают поиск по определённому столбцу, индекс по этому столбцу может значительно ускорить эти операции. Например, если вы часто ищете пользователей по их email, стоит создать индекс по столбцу email.

### Условия в запросах (WHERE)

Индексы очень полезны для условий фильтрации в запросах, особенно когда они включают большие объёмы данных.

### Сортировка данных (ORDER BY)

Если запросы часто требуют сортировки по определённому полю, индекс по этому полю поможет ускорить процесс сортировки, так как данные в индексе уже будут частично или полностью упорядочены.

### Операции объединения (JOIN)

Индексы на полях, используемых для соединения таблиц, могут значительно ускорить эти операции, особенно при работе с большими таблицами.

### Агрегация данных (GROUP BY)

Индексы могут ускорить группировку данных, если группировка происходит по индексированным полям.

---

индекс — это структура данных, которая улучшает скорость операций выборки данных из таблицы базы данных. Они строятся на основе одного или нескольких столбцов таблицы и позволяют быстро находить строки без необходимости сканировать всю таблицу.

Зачем они нужны?

1️⃣Ускорение поиска: Позволяют базе данных быстрее находить и извлекать данные. Без индексов СУБД приходится выполнять полный поиск по всей таблице (full table scan), что может быть очень неэффективно для больших объемов данных.
2️⃣Эффективность запросов: Особенно важны для улучшения производительности запросов, содержащих условия WHERE, ORDER BY, GROUP BY и JOIN.
3️⃣Уникальность: Можно использовать для обеспечения уникальности данных в столбце, предотвращая дублирование записей.

Как они работают?

Обычно реализуются с использованием структур данных, таких как B-деревья или хеш-таблицы. Каждый индекс содержит указатели на строки основной таблицы, что позволяет СУБД быстро переходить к нужным данным без полного перебора таблицы.

✅B-дерево: Наиболее часто используемая структура для индексов, которая поддерживает порядок и быстрый поиск, вставку, удаление и обход элементов. Она эффективно работает с операциями поиска на основе диапазонов.
✅Хеш-таблица: Лучше подходит для операций с точечным поиском, где используются условия эквивалентности.

Типы:

1️⃣Основной индекс (Primary index): созданный на первичном ключе таблицы.
2️⃣Вторичный индекс (Secondary index): на одном или нескольких столбцах, которые не являются первичным ключом.
3️⃣Уникальный индекс: Гарантирует, что все значения в индексе уникальны.
4️⃣Составной индекс: Включает несколько столбцов.

Создание индекса для столбца email в таблице users для ускорения поиска по электронной почте:
CREATE INDEX idx_email ON users(email);

Этот индекс позволит СУБД быстрее находить записи, осуществляя поиск по столбцу email, благодаря предварительно построенной структуре индекса.

Хотя индексы значительно ускоряют чтение данных, они также добавляют накладные расходы на операции записи, такие как вставка, обновление и удаление записей, так как при каждой такой операции необходимо также обновлять индекс. Кроме того, индексы занимают дополнительное место в памяти или на диске. Поэтому важно тщательно планировать, какие индексы создавать и как их поддерживать.
