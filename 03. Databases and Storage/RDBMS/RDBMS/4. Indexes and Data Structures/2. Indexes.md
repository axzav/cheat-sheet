# Indexes

Index (индекс) — структура данных, которая улучшает скорость операций выборки данных из таблицы базы данных. Индексы строятся на основе одного или нескольких столбцов таблицы и позволяют быстро находить строки без необходимости сканировать всю таблицу (full table scan).

Индексы можно сравнить с оглавлением книги: вместо того, чтобы просматривать всю книгу, система может обратиться к индексу, чтобы быстро найти нужную информацию.

## Зачем нужны индексы

### Ускорение поиска
Позволяют базе данных быстрее находить и извлекать данные. Без индексов СУБД приходится выполнять полный поиск по всей таблице, что может быть очень неэффективно для больших объемов данных.

### Эффективность запросов
Особенно важны для улучшения производительности запросов, содержащих условия WHERE, ORDER BY, GROUP BY и JOIN.

### Обеспечение уникальности
Можно использовать для обеспечения уникальности данных в столбце, предотвращая дублирование записей.

## Как работают индексы

Обычно реализуются с использованием структур данных, таких как B-tree или hash-таблицы. Каждый индекс содержит указатели на строки основной таблицы, что позволяет СУБД быстро переходить к нужным данным без полного перебора таблицы.

- **B-tree**: Наиболее часто используемая структура для индексов, которая поддерживает порядок и быстрый поиск, вставку, удаление и обход элементов. Эффективно работает с операциями поиска на основе диапазонов.
- **Hash-таблица**: Лучше подходит для операций с точечным поиском, где используются условия эквивалентности.

## Основные случаи использования

### Поиск по ключевым столбцам
Если запросы часто включают поиск по определенному столбцу, индекс по этому столбцу может значительно ускорить эти операции. Например, если часто ищут пользователей по их email, стоит создать индекс по столбцу email.

### Условия в запросах (WHERE)
Индексы очень полезны для условий фильтрации в запросах, особенно когда они включают большие объемы данных.

### Сортировка данных (ORDER BY)
Если запросы часто требуют сортировки по определенному полю, индекс по этому полю поможет ускорить процесс сортировки, так как данные в индексе уже будут частично или полностью упорядочены.

### Операции объединения (JOIN)
Индексы на полях, используемых для соединения таблиц, могут значительно ускорить эти операции, особенно при работе с большими таблицами.

### Агрегация данных (GROUP BY)
Индексы могут ускорить группировку данных, если группировка происходит по индексированным полям.

## Типы индексов

### Primary Index (Основной индекс)
Созданный на primary key таблицы. Создается автоматически при определении primary key.

### Secondary Index (Вторичный индекс)
Индекс на одном или нескольких столбцах, которые не являются primary key.

### Unique Index (Уникальный индекс)
Гарантирует, что все значения в индексе уникальны.

### Composite Index (Составной индекс)
Включает несколько столбцов. Порядок столбцов важен.

## Создание индексов

```sql
-- Простой индекс
CREATE INDEX idx_email ON users(email);

-- Уникальный индекс
CREATE UNIQUE INDEX idx_email_unique ON users(email);

-- Составной индекс
CREATE INDEX idx_name_email ON users(last_name, first_name, email);

-- Удаление индекса
DROP INDEX idx_email ON users;
```

## Преимущества и недостатки

### Преимущества
- Значительно ускоряют операции чтения
- Улучшают производительность JOIN операций
- Ускоряют сортировку и группировку
- Обеспечивают уникальность данных

### Недостатки
- Добавляют накладные расходы на операции записи (INSERT, UPDATE, DELETE)
- Занимают дополнительное место в памяти или на диске
- Требуют обслуживания и обновления при изменении данных

## Рекомендации

1. Создавать индексы на столбцах, часто используемых в WHERE, JOIN, ORDER BY
2. Избегать избыточных индексов на редко используемых столбцах
3. Мониторить использование индексов и удалять неиспользуемые
4. Учитывать баланс между скоростью чтения и накладными расходами на запись
5. Использовать составные индексы для запросов с несколькими условиями
