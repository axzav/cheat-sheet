# Триггеры (Triggers)

Триггеры — объекты базы данных, которые автоматически выполняются в ответ на определенные события (INSERT, UPDATE, DELETE) на таблице.

## Создание триггеров

### PostgreSQL

```sql
CREATE TRIGGER trigger_name
    BEFORE | AFTER | INSTEAD OF
    INSERT | UPDATE | DELETE
    ON table_name
    FOR EACH ROW | FOR EACH STATEMENT
    EXECUTE FUNCTION function_name();
```

### MySQL

```sql
CREATE TRIGGER trigger_name
    BEFORE | AFTER
    INSERT | UPDATE | DELETE
    ON table_name
    FOR EACH ROW
    BEGIN
        -- тело триггера
    END;
```

## Время выполнения (Timing)

- **BEFORE** — выполняется до события. Можно изменить данные перед их сохранением
- **AFTER** — выполняется после события. Используется для логирования и обновления связанных таблиц
- **INSTEAD OF** — заменяет событие (только в PostgreSQL, для представлений)

## Область действия (Scope)

- **FOR EACH ROW** — выполняется один раз для каждой затронутой строки
- **FOR EACH STATEMENT** — выполняется один раз для оператора (только PostgreSQL)

## Пример: журнал аудита

### PostgreSQL

```sql
-- Создание функции триггера
CREATE OR REPLACE FUNCTION audit_log()
RETURNS TRIGGER AS $$
BEGIN
    INSERT INTO audit_table (table_name, action, timestamp, user_id)
    VALUES (TG_TABLE_NAME, TG_OP, NOW(), current_user);
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

-- Создание триггера
CREATE TRIGGER users_audit
    AFTER INSERT OR UPDATE OR DELETE
    ON users
    FOR EACH ROW
    EXECUTE FUNCTION audit_log();
```

### MySQL

```sql
-- Создание триггера
CREATE TRIGGER users_audit_insert
AFTER INSERT ON users
FOR EACH ROW
BEGIN
    INSERT INTO audit_table (table_name, action, timestamp)
    VALUES ('users', 'INSERT', NOW());
END;

CREATE TRIGGER users_audit_update
AFTER UPDATE ON users
FOR EACH ROW
BEGIN
    INSERT INTO audit_table (table_name, action, timestamp)
    VALUES ('users', 'UPDATE', NOW());
END;

CREATE TRIGGER users_audit_delete
AFTER DELETE ON users
FOR EACH ROW
BEGIN
    INSERT INTO audit_table (table_name, action, timestamp)
    VALUES ('users', 'DELETE', NOW());
END;
```

## Доступ к данным строки

### PostgreSQL

- `NEW` — новая строка (для INSERT и UPDATE)
- `OLD` — старая строка (для UPDATE и DELETE)

```sql
CREATE OR REPLACE FUNCTION log_user_changes()
RETURNS TRIGGER AS $$
BEGIN
    IF TG_OP = 'INSERT' THEN
        INSERT INTO user_changes_log (user_id, action, old_value, new_value, changed_at)
        VALUES (NEW.id, 'INSERT', NULL, NEW.email, NOW());
        RETURN NEW;
    ELSIF TG_OP = 'UPDATE' THEN
        INSERT INTO user_changes_log (user_id, action, old_value, new_value, changed_at)
        VALUES (NEW.id, 'UPDATE', OLD.email, NEW.email, NOW());
        RETURN NEW;
    ELSIF TG_OP = 'DELETE' THEN
        INSERT INTO user_changes_log (user_id, action, old_value, new_value, changed_at)
        VALUES (OLD.id, 'DELETE', OLD.email, NULL, NOW());
        RETURN OLD;
    END IF;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER user_changes_trigger
    AFTER INSERT OR UPDATE OR DELETE
    ON users
    FOR EACH ROW
    EXECUTE FUNCTION log_user_changes();
```

### MySQL

- `NEW.column_name` — значения новой строки
- `OLD.column_name` — значения старой строки

```sql
CREATE TRIGGER log_user_email_changes
AFTER UPDATE ON users
FOR EACH ROW
BEGIN
    IF OLD.email != NEW.email THEN
        INSERT INTO user_changes_log (user_id, old_email, new_email, changed_at)
        VALUES (NEW.id, OLD.email, NEW.email, NOW());
    END IF;
END;
```

## Пример: автоматическое обновление timestamp

```sql
-- PostgreSQL
CREATE OR REPLACE FUNCTION update_updated_at()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at = NOW();
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER update_users_updated_at
    BEFORE UPDATE ON users
    FOR EACH ROW
    EXECUTE FUNCTION update_updated_at();
```

```sql
-- MySQL
CREATE TRIGGER update_users_updated_at
BEFORE UPDATE ON users
FOR EACH ROW
SET NEW.updated_at = NOW();
```

## Пример: валидация данных

```sql
-- PostgreSQL
CREATE OR REPLACE FUNCTION validate_user_age()
RETURNS TRIGGER AS $$
BEGIN
    IF NEW.age < 18 THEN
        RAISE EXCEPTION 'User must be at least 18 years old';
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER validate_user_age_trigger
    BEFORE INSERT OR UPDATE ON users
    FOR EACH ROW
    EXECUTE FUNCTION validate_user_age();
```

## Пример: автоматические вычисления

```sql
-- Обновление суммы заказа при изменении позиций
CREATE OR REPLACE FUNCTION update_order_total()
RETURNS TRIGGER AS $$
BEGIN
    UPDATE orders
    SET total = (
        SELECT COALESCE(SUM(quantity * price), 0)
        FROM order_items
        WHERE order_id = COALESCE(NEW.order_id, OLD.order_id)
    )
    WHERE id = COALESCE(NEW.order_id, OLD.order_id);
    
    RETURN COALESCE(NEW, OLD);
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER update_order_total_on_insert
    AFTER INSERT ON order_items
    FOR EACH ROW
    EXECUTE FUNCTION update_order_total();

CREATE TRIGGER update_order_total_on_update
    AFTER UPDATE ON order_items
    FOR EACH ROW
    EXECUTE FUNCTION update_order_total();

CREATE TRIGGER update_order_total_on_delete
    AFTER DELETE ON order_items
    FOR EACH ROW
    EXECUTE FUNCTION update_order_total();
```

## Удаление триггеров

```sql
-- PostgreSQL
DROP TRIGGER trigger_name ON table_name;

-- MySQL
DROP TRIGGER trigger_name;
```

## Просмотр триггеров

```sql
-- PostgreSQL
SELECT * FROM information_schema.triggers 
WHERE trigger_name = 'trigger_name';

-- MySQL
SHOW TRIGGERS FROM database_name;
SHOW TRIGGERS LIKE 'trigger_name';
```

## Применение триггеров

### Журналирование изменений

Отслеживание всех изменений данных для аудита и отладки.

### Валидация данных

Проверка бизнес-правил на уровне базы данных перед сохранением.

### Автоматические вычисления

Обновление связанных таблиц при изменении данных.

### Уведомления об изменениях

Уведомление других систем о произошедших изменениях.

## Рекомендации

- Держать триггеры простыми и быстрыми
- Избегать рекурсивных триггеров
- Документировать логику триггеров
- Учитывать влияние на производительность
- Использовать умеренно — предпочитать логику приложения, когда возможно
- Тестировать триггеры на различных сценариях
