# Transactions

Transactions ensure that a series of database operations either all succeed or all fail, maintaining data consistency.

## Basic Transaction Syntax

### PostgreSQL / MySQL
```sql
BEGIN;  -- or START TRANSACTION;
-- SQL statements
COMMIT;  -- or ROLLBACK;
```

### Auto-commit
By default, each statement is automatically committed. Use transactions to group multiple statements.

## Transaction Properties (ACID)

- **Atomicity**: All or nothing
- **Consistency**: Database remains in valid state
- **Isolation**: Concurrent transactions don't interfere
- **Durability**: Committed changes persist

## Transaction Control

### Commit
```sql
COMMIT;  -- Save all changes
```

### Rollback
```sql
ROLLBACK;  -- Undo all changes in transaction
```

### Savepoints
```sql
BEGIN;
-- some operations
SAVEPOINT sp1;
-- more operations
ROLLBACK TO SAVEPOINT sp1;  -- Rollback to savepoint
-- continue or
COMMIT;
```

## Transaction Isolation Levels

See "Isolation levels.md" in Transactions and Concurrency Control section for details.

## Nested Transactions

Most databases don't support true nested transactions, but savepoints provide similar functionality.

## Best Practices

1. Keep transactions short
2. Don't hold locks unnecessarily
3. Handle errors properly
4. Use appropriate isolation level
5. Avoid long-running transactions
6. Test rollback scenarios
