# Представления (Views)

Представления (Views) — виртуальные таблицы, основанные на результате SQL-запроса. Не хранят данные сами по себе, но предоставляют способ упрощения сложных запросов и контроля доступа к данным.

## Создание представлений

### Базовый синтаксис

```sql
CREATE VIEW view_name AS
SELECT column1, column2, ...
FROM table_name
WHERE condition;
```

### Пример

```sql
CREATE VIEW active_users AS
SELECT id, username, email
FROM users
WHERE status = 'active';
```

## Использование представлений

Представления можно использовать как обычные таблицы:

```sql
SELECT * FROM active_users;

SELECT username, email 
FROM active_users 
WHERE email LIKE '%@gmail.com';
```

## Обновление представлений

### PostgreSQL

```sql
CREATE OR REPLACE VIEW view_name AS
SELECT ...;
```

### MySQL

```sql
ALTER VIEW view_name AS
SELECT ...;
```

### Пример обновления

```sql
-- PostgreSQL
CREATE OR REPLACE VIEW active_users AS
SELECT id, username, email, last_login
FROM users
WHERE status = 'active' AND last_login > CURRENT_DATE - INTERVAL '30 days';
```

## Удаление представлений

```sql
DROP VIEW view_name;

-- С проверкой существования
DROP VIEW IF EXISTS view_name;
```

## Материализованные представления (Materialized Views)

Материализованные представления физически хранят результаты запроса и могут быть обновлены вручную или автоматически.

### PostgreSQL

```sql
-- Создание материализованного представления
CREATE MATERIALIZED VIEW mv_sales_summary AS
SELECT 
    product_id,
    DATE_TRUNC('month', sale_date) AS month,
    SUM(amount) AS total_sales,
    COUNT(*) AS sale_count
FROM sales
GROUP BY product_id, DATE_TRUNC('month', sale_date);

-- Обновление материализованного представления
REFRESH MATERIALIZED VIEW mv_sales_summary;

-- Обновление с одновременным пересозданием
REFRESH MATERIALIZED VIEW CONCURRENTLY mv_sales_summary;

-- Использование
SELECT * FROM mv_sales_summary;
```

### MySQL

MySQL не поддерживает нативные материализованные представления, но их можно симулировать с помощью обычных таблиц:

```sql
-- Создание таблицы для хранения агрегированных данных
CREATE TABLE mv_sales_summary AS
SELECT 
    product_id,
    DATE_FORMAT(sale_date, '%Y-%m') AS month,
    SUM(amount) AS total_sales,
    COUNT(*) AS sale_count
FROM sales
GROUP BY product_id, DATE_FORMAT(sale_date, '%Y-%m');

-- Обновление через процедуру или триггер
```

## Обновляемые представления (Updatable Views)

Некоторые представления можно обновлять (INSERT, UPDATE, DELETE), если они соответствуют определенным условиям:

### Условия для обновляемых представлений

- Основаны на одной таблице
- Не используют `DISTINCT`, `GROUP BY` или агрегатные функции
- Включают все столбцы с ограничением `NOT NULL`
- Не используют оконные функции в некоторых СУБД

### Пример обновляемого представления

```sql
-- Создание обновляемого представления
CREATE VIEW user_emails AS
SELECT id, username, email
FROM users
WHERE status = 'active';

-- Обновление через представление
UPDATE user_emails 
SET email = 'newemail@example.com' 
WHERE id = 1;

-- Вставка через представление
INSERT INTO user_emails (username, email)
VALUES ('newuser', 'newuser@example.com');

-- Удаление через представление
DELETE FROM user_emails WHERE id = 1;
```

## Представления с JOIN

```sql
CREATE VIEW user_orders AS
SELECT 
    u.username,
    u.email,
    o.order_date,
    o.total,
    o.status
FROM users u
INNER JOIN orders o ON u.id = o.user_id;

-- Использование
SELECT * FROM user_orders WHERE status = 'completed';
```

## Представления с агрегацией

```sql
CREATE VIEW department_stats AS
SELECT 
    d.name AS department_name,
    COUNT(e.id) AS employee_count,
    AVG(e.salary) AS avg_salary,
    MAX(e.salary) AS max_salary
FROM departments d
LEFT JOIN employees e ON d.id = e.department_id
GROUP BY d.id, d.name;
```

## Преимущества представлений

### Упрощение запросов

Скрывают сложность запросов за простым интерфейсом:

```sql
-- Вместо сложного запроса каждый раз
SELECT * FROM user_orders WHERE status = 'completed';
```

### Безопасность

Контроль доступа к конкретным столбцам и строкам:

```sql
-- Представление только с публичными данными
CREATE VIEW public_user_info AS
SELECT id, username, created_at
FROM users
WHERE status = 'active';
```

### Консистентность

Предоставляют единообразный интерфейс к данным:

```sql
-- Изменение структуры таблицы не требует изменения запросов,
-- использующих представление
```

### Абстракция

Скрывают изменения в структуре базовых таблиц от приложений.

## Ограничения

- Производительность — представления выполняют запрос каждый раз при обращении
- Ограничения на обновление — не все представления можно обновлять
- Зависимости — изменение базовых таблиц может сломать представление

## Рекомендации

- Использовать представления для упрощения часто используемых сложных запросов
- Применять материализованные представления для дорогих агрегаций
- Документировать назначение и структуру представлений
- Регулярно проверять производительность запросов к представлениям
