# Рекурсивные CTE

Рекурсивные CTE (Recursive Common Table Expressions) позволяют выполнять итеративные вычисления и обрабатывать иерархические структуры данных.

## Синтаксис

Рекурсивный CTE состоит из двух частей:

1. **Anchor member** (якорный запрос) — базовая часть, возвращающая начальные строки
2. **Recursive member** (рекурсивный запрос) — часть, которая ссылается на сам CTE и продолжает итерацию

```sql
WITH RECURSIVE cte_name AS (
    -- Anchor member
    SELECT ...
    UNION [ALL]
    -- Recursive member
    SELECT ... FROM cte_name WHERE ...
)
SELECT * FROM cte_name;
```

## Важные ограничения

- В рекурсивной части нельзя использовать `ORDER BY` (кроме финального SELECT)
- Необходимо условие остановки рекурсии, иначе запрос будет выполняться бесконечно
- `UNION ALL` позволяет дубликаты, `UNION` их удаляет

## Примеры

### Вычисление чисел Фибоначчи

```sql
WITH RECURSIVE fib AS (
    -- Anchor: первые два числа
    SELECT 1 AS n, 1 AS fibn, 1 AS fibn1
    UNION ALL
    -- Recursive: следующее число
    SELECT 
        n + 1,
        fibn1,
        fibn + fibn1
    FROM fib
    WHERE n < 20  -- условие остановки
)
SELECT n, fibn AS fibonacci_number 
FROM fib;
```

### Обход иерархии (дерева)

```sql
-- Таблица с иерархией сотрудников
CREATE TABLE employees (
    id INT PRIMARY KEY,
    name VARCHAR(100),
    manager_id INT REFERENCES employees(id)
);

-- Найти всех подчиненных конкретного менеджера
WITH RECURSIVE subordinates AS (
    -- Anchor: начальный менеджер
    SELECT id, name, manager_id, 0 AS level
    FROM employees
    WHERE id = 1  -- ID начального менеджера
    UNION ALL
    -- Recursive: подчиненные
    SELECT 
        e.id, 
        e.name, 
        e.manager_id,
        s.level + 1
    FROM employees e
    INNER JOIN subordinates s ON e.manager_id = s.id
)
SELECT * FROM subordinates;
```

### Накопительный расчет

```sql
-- Расчет накопленного денежного потока
WITH RECURSIVE cash_flow_calc AS (
    -- Anchor: первая транзакция
    SELECT 
        date, 
        cash_flow, 
        cash_flow AS cumulative,
        1 AS level
    FROM transactions 
    WHERE id = 1
    UNION ALL
    -- Recursive: следующие транзакции
    SELECT 
        t.date, 
        t.cash_flow, 
        c.cumulative + t.cash_flow AS cumulative,
        c.level + 1
    FROM transactions t
    JOIN cash_flow_calc c ON t.date > c.date
    WHERE t.id = (
        SELECT id FROM transactions 
        WHERE date > c.date 
        ORDER BY date ASC 
        LIMIT 1
    )
)
SELECT * FROM cash_flow_calc;
```

### Обход графа

```sql
-- Найти все связанные узлы в графе
WITH RECURSIVE graph_traversal AS (
    -- Anchor: начальный узел
    SELECT node_id, 0 AS depth
    FROM graph
    WHERE node_id = 'A'
    UNION ALL
    -- Recursive: связанные узлы
    SELECT 
        g.target_node,
        gt.depth + 1
    FROM graph g
    JOIN graph_traversal gt ON g.source_node = gt.node_id
    WHERE gt.depth < 10  -- ограничение глубины
)
SELECT DISTINCT node_id FROM graph_traversal;
```

## Рекомендации

- Всегда добавлять условие остановки рекурсии
- Ограничивать глубину рекурсии для предотвращения бесконечных циклов
- Использовать `UNION ALL` для производительности, если дубликаты допустимы
- Тестировать на небольших наборах данных перед применением к большим таблицам
