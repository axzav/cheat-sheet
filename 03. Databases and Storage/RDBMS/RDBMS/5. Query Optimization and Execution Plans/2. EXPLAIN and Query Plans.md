# EXPLAIN and Query Plans

EXPLAIN is a SQL command that shows how the database will execute a query. It's essential for understanding query performance and optimization.

## Basic Usage

```sql
EXPLAIN SELECT * FROM users WHERE email = 'user@example.com';
```

## EXPLAIN ANALYZE

Shows the actual execution plan with runtime statistics:

```sql
EXPLAIN ANALYZE SELECT * FROM users WHERE email = 'user@example.com';
```

## Key Metrics to Understand

- **Execution Time**: Total time to execute the query
- **Planning Time**: Time spent planning the query
- **Seq Scan**: Sequential scan (usually slow for large tables)
- **Index Scan**: Using an index (usually faster)
- **Cost**: Estimated cost of the operation
- **Rows**: Number of rows processed
- **Filter**: Conditions applied to filter rows

## Common Execution Plan Operations

- **Seq Scan**: Full table scan
- **Index Scan**: Scanning an index
- **Index Only Scan**: Reading only from index (fastest)
- **Bitmap Heap Scan**: Using bitmap index
- **Nested Loop**: Join operation
- **Hash Join**: Hash-based join
- **Merge Join**: Merge-based join
- **Sort**: Sorting operation
- **Aggregate**: Aggregation operation

## Optimization Tips

1. Look for sequential scans on large tables - may need indexes
2. Check if indexes are being used
3. Verify join methods are appropriate
4. Watch for expensive operations like sorts on large datasets
5. Use EXPLAIN ANALYZE to see actual vs estimated costs

## PostgreSQL Specific

```sql
-- Show detailed query plan
EXPLAIN (ANALYZE, BUFFERS, VERBOSE) SELECT ...;

-- Show JSON format
EXPLAIN (FORMAT JSON) SELECT ...;
```

## MySQL Specific

```sql
-- Show extended information
EXPLAIN EXTENDED SELECT ...;

-- Show warnings
EXPLAIN SELECT ...;
SHOW WARNINGS;
```
