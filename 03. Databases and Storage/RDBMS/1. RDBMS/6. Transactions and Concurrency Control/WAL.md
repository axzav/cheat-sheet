# Write-Ahead Logging (WAL)

Write-Ahead Logging (WAL) — механизм обеспечения долговечности (durability) транзакций, при котором все изменения сначала записываются в журнал транзакций (transaction log), а затем применяются к данным.

## Принцип работы

### Основное правило

**Изменения должны быть записаны в WAL до того, как они будут записаны в основные файлы данных.**

Это гарантирует, что даже при сбое системы можно восстановить данные, применив записи из WAL.

### Последовательность операций

1. Транзакция выполняет изменение данных
2. Изменение записывается в WAL (журнал транзакций)
3. WAL синхронизируется на диск (fsync)
4. Транзакция считается зафиксированной
5. Изменения применяются к основным данным (может быть отложено)

## Преимущества WAL

### Производительность

- **Последовательная запись**: WAL записывается последовательно, что быстрее случайных записей
- **Групповые коммиты**: Несколько транзакций могут быть зафиксированы одной операцией записи
- **Отложенная запись данных**: Основные данные могут обновляться асинхронно

### Надежность

- **Долговечность**: Гарантия сохранения данных даже при сбое
- **Восстановление**: Возможность восстановления данных из WAL
- **Point-in-time recovery**: Восстановление на определенный момент времени

## Структура WAL

### WAL сегменты

WAL разбит на сегменты фиксированного размера (обычно 16MB в PostgreSQL):

- Каждый сегмент имеет уникальный номер
- Старые сегменты удаляются после checkpoint
- Сегменты могут быть архивированы для восстановления

### WAL записи

Каждая запись содержит:

- **LSN (Log Sequence Number)**: Уникальный идентификатор записи
- **XID (Transaction ID)**: Идентификатор транзакции
- **Изменения данных**: Информация об измененных данных
- **Метаданные**: Временные метки, типы операций

## Checkpoint

Checkpoint — процесс синхронизации данных из WAL в основные файлы данных.

### Функции checkpoint

- Применяет все зафиксированные изменения к данным
- Освобождает место в WAL, удаляя старые сегменты
- Создает точку восстановления

### Настройка checkpoint

**PostgreSQL**:

```sql
-- Проверить настройки checkpoint
SHOW checkpoint_timeout;
SHOW max_wal_size;
SHOW min_wal_size;

-- Принудительный checkpoint
CHECKPOINT;
```

## Восстановление из WAL

### Crash Recovery

При запуске после сбоя СУБД:

1. Находит последний checkpoint
2. Читает WAL записи после checkpoint
3. Применяет все зафиксированные транзакции
4. Откатывает незафиксированные транзакции

### Point-in-Time Recovery (PITR)

Восстановление на определенный момент времени:

1. Восстановление из резервной копии
2. Применение WAL сегментов до нужного момента
3. Остановка на указанном времени

## Настройка WAL

### PostgreSQL

```sql
-- Режимы синхронизации WAL
-- fsync: полная синхронизация (надежно, медленно)
-- synchronous_commit: синхронный коммит
SHOW synchronous_commit;

-- Размер WAL сегментов
SHOW wal_segment_size;

-- Архивация WAL
SHOW archive_mode;
SHOW archive_command;
```

### Торговые компромиссы

- **synchronous_commit = on**: Максимальная надежность, но медленнее
- **synchronous_commit = off**: Быстрее, но возможна потеря последних транзакций при сбое
- **fsync = off**: Очень быстро, но опасно (не рекомендуется для production)

## WAL и репликация

WAL используется для репликации данных:

- **Streaming Replication**: Передача WAL записей в реальном времени
- **Logical Replication**: Применение изменений на основе WAL
- **Standby серверы**: Применяют WAL для синхронизации с master

## Мониторинг WAL

### PostgreSQL

```sql
-- Размер WAL
SELECT pg_size_pretty(pg_wal_lsn_diff(pg_current_wal_lsn(), '0/0'));

-- Текущая позиция WAL
SELECT pg_current_wal_lsn();

-- Статистика WAL
SELECT * FROM pg_stat_wal;
```

## Оптимизация WAL

- Настройка размера WAL сегментов
- Оптимизация частоты checkpoint
- Использование WAL сжатия (PostgreSQL 13+)
- Настройка архивации для больших нагрузок
