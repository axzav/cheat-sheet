# MVCC и видимость данных

MVCC (Multi-Version Concurrency Control) — механизм управления конкурентностью, который позволяет нескольким транзакциям работать с данными одновременно, не блокируя друг друга при чтении.

## Принцип работы MVCC

Вместо блокировок при чтении, MVCC создает несколько версий одной и той же строки. Каждая транзакция видит снимок данных (snapshot) на момент своего начала.

### Основные концепции

- **Версионирование строк**: Каждое изменение создает новую версию строки
- **Снимок данных (Snapshot)**: Моментальный снимок состояния данных на определенный момент времени
- **Видимость версий**: Транзакция видит только те версии, которые были зафиксированы до её начала

## Механизм видимости

### Идентификаторы транзакций

Каждая транзакция получает уникальный идентификатор (Transaction ID, XID):

- **xmin**: ID транзакции, которая создала версию строки
- **xmax**: ID транзакции, которая удалила версию строки (или NULL, если строка не удалена)

### Правила видимости

Версия строки видна транзакции, если:

1. **xmin** зафиксирован до начала текущей транзакции
2. **xmax** равен NULL или не зафиксирован до начала текущей транзакции
3. Версия не была удалена текущей транзакцией

### Пример работы

```
Время T1: Транзакция A (XID=100) создает строку с xmin=100
Время T2: Транзакция B (XID=101) начинается
Время T3: Транзакция A коммитится
Время T4: Транзакция B читает строку - видит её, так как xmin=100 зафиксирован
Время T5: Транзакция C (XID=102) обновляет строку, создавая новую версию с xmin=102
Время T6: Транзакция B читает строку - видит старую версию (xmin=100), так как новая версия (xmin=102) еще не зафиксирована
```

## Преимущества MVCC

- **Отсутствие блокировок при чтении**: Чтение не блокирует запись и наоборот
- **Высокая конкурентность**: Множество транзакций могут работать одновременно
- **Консистентные снимки**: Каждая транзакция видит согласованное состояние данных
- **Меньше deadlocks**: Отсутствие блокировок при чтении снижает вероятность взаимоблокировок

## Недостатки MVCC

- **Дополнительное место для хранения**: Старые версии строк занимают место
- **Необходимость очистки**: Старые версии нужно периодически удалять (VACUUM в PostgreSQL)
- **Накладные расходы**: Проверка видимости версий требует дополнительных вычислений

## Очистка старых версий

### VACUUM (PostgreSQL)

Удаляет старые версии строк, которые больше не нужны:

```sql
-- Автоматическая очистка
VACUUM;

-- Полная очистка с обновлением статистики
VACUUM ANALYZE;

-- Агрессивная очистка
VACUUM FULL;
```

### Автоматическая очистка

PostgreSQL автоматически запускает VACUUM для удаления старых версий, но иногда требуется ручной запуск для больших таблиц.

## Уровни изоляции и MVCC

MVCC по-разному работает на разных уровнях изоляции:

- **Read Committed**: Каждый запрос видит снимок на момент его выполнения
- **Repeatable Read**: Вся транзакция видит снимок на момент её начала
- **Serializable**: Использует дополнительные механизмы для предотвращения аномалий сериализации

## Примеры использования

### Чтение без блокировок

```sql
-- Транзакция A
BEGIN;
SELECT * FROM accounts WHERE id = 1;  -- Читает без блокировки
COMMIT;

-- Транзакция B может одновременно обновлять данные
BEGIN;
UPDATE accounts SET balance = balance + 100 WHERE id = 1;
COMMIT;
```

### Видимость изменений

```sql
-- Транзакция A
BEGIN;
SELECT balance FROM accounts WHERE id = 1;  -- Видит 1000

-- Транзакция B (в другом соединении)
BEGIN;
UPDATE accounts SET balance = 2000 WHERE id = 1;
COMMIT;

-- Транзакция A (продолжение)
SELECT balance FROM accounts WHERE id = 1;  -- Все еще видит 1000 (на уровне Repeatable Read)
COMMIT;
```

## Реализация в различных СУБД

- **PostgreSQL**: Полная поддержка MVCC с версионированием строк
- **MySQL InnoDB**: Использует MVCC с undo logs
- **Oracle**: Использует MVCC с undo segments
- **SQL Server**: Использует MVCC начиная с версии 2005 (snapshot isolation)
