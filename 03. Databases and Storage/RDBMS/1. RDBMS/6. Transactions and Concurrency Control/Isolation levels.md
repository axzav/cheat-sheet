# Уровни изоляции транзакций

Уровни изоляции транзакций — это концепция в управлении базами данных, которая определяет, как одна транзакция видит изменения, сделанные другими транзакциями. Они помогают предотвратить различные виды конфликтов и обеспечивают целостность данных. Существует четыре основных уровня изоляции транзакций, определенных стандартом SQL.

Уровни изоляции нужны, чтобы управлять конкурентным доступом к данным и обеспечить их целостность в многопользовательских системах.

## Основные проблемы конкурентного доступа

Прежде чем углубиться в уровни изоляции, важно понимать проблемы, которые они помогают решить:

- **Грязное чтение (Dirty Read)**: Одна транзакция видит незавершенные изменения другой транзакции.
- **Неповторяющееся чтение (Non-repeatable Read)**: Одна транзакция читает те же строки несколько раз и видит разные данные из-за изменений, сделанных другой транзакцией.
- **Фантомное чтение (Phantom Read)**: Одна транзакция видит новые строки, добавленные другой транзакцией, при повторном выполнении запроса.
- **Потерянное обновление (Lost Update)**: Две транзакции одновременно читают одно значение, изменяют его и записывают обратно, в результате одно из обновлений теряется. Решается через атомарные обновления, явные блокировки или обнаружение потерянных обновлений (если менеджер транзакций видит, что какое-то обновление приведет к потере данных, то он автоматически откатывает такую транзакцию).

## Уровни изоляции

### Read Uncommitted (Чтение незафиксированных данных)

Транзакция может читать данные, измененные другими транзакциями, даже если эти изменения еще не зафиксированы.

**Проблемы**: Возможны грязные чтения, неповторяющиеся чтения и фантомные чтения.

**Пример**: Транзакция A изменяет строку, но не фиксирует изменения. Транзакция B читает эту измененную строку. Если транзакция A откатится, данные, которые видела транзакция B, окажутся неверными.

### Read Committed (Чтение зафиксированных данных)

Транзакция может читать только те данные, которые были зафиксированы другими транзакциями. Это уровень изоляции по умолчанию в большинстве СУБД.

**Проблемы**: Исключает грязные чтения, но возможны неповторяющиеся чтения и фантомные чтения.

**Пример**: Транзакция A изменяет строку и фиксирует изменения. Транзакция B читает измененную строку. Если транзакция A снова изменяет ту же строку и фиксирует изменения, транзакция B увидит разные данные при повторном чтении.

### Repeatable Read (Повторяемое чтение)

Гарантирует, что если транзакция прочитала строку, то другие транзакции не смогут изменить или удалить эту строку до завершения первой транзакции.

**Проблемы**: Исключает грязные чтения и неповторяющиеся чтения, но возможны фантомные чтения.

**Пример**: Транзакция A читает набор строк. Если транзакция B изменяет одну из этих строк и фиксирует изменения, транзакция A не увидит эти изменения до завершения.

### Serializable (Сериализуемость)

Обеспечивает полную изоляцию транзакций, делая их выполнение последовательным, как если бы они выполнялись одна за другой.

**Проблемы**: Исключает грязные чтения, неповторяющиеся чтения и фантомные чтения. Самый строгий уровень изоляции, но может приводить к блокировкам и снижению производительности.

**Пример**: Транзакция A выполняет запрос, который включает диапазон строк. Транзакция B не может вставить, изменить или удалить строки, попадающие в этот диапазон, до завершения транзакции A.

## Сравнительная таблица

| Уровень изоляции | Грязное чтение | Неповторяющееся чтение | Фантомное чтение |
|------------------|----------------|------------------------|------------------|
| Read Uncommitted | Возможно       | Возможно               | Возможно         |
| Read Committed   | Нет            | Возможно               | Возможно         |
| Repeatable Read  | Нет            | Нет                    | Возможно         |
| Serializable     | Нет            | Нет                    | Нет              |

## Установка уровня изоляции

### PostgreSQL

```sql
SET TRANSACTION ISOLATION LEVEL READ COMMITTED;
BEGIN;
-- операции транзакции
COMMIT;
```

### MySQL

```sql
SET TRANSACTION ISOLATION LEVEL REPEATABLE READ;
START TRANSACTION;
-- операции транзакции
COMMIT;
```
