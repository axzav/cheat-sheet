# Оптимизация запросов

Оптимизация запросов — процесс улучшения производительности SQL-запросов для уменьшения времени выполнения и использования ресурсов.

## Основные принципы оптимизации

### Индексирование (Indexing)

Индексы ускоряют поиск данных, но замедляют операции записи.

- **B-tree индексы** — стандартные индексы для большинства случаев
- **Hash индексы** — для точных совпадений (равенство)
- **GIN (Generalized Inverted Index)** — для полнотекстового поиска и массивов
- **GiST (Generalized Search Tree)** — для геоданных и сложных типов данных
- **BRIN (Block Range Index)** — для больших таблиц с упорядоченными данными

### Стратегии индексирования

- Индексировать колонки, используемые в WHERE, JOIN, ORDER BY
- Избегать избыточных индексов (замедляют INSERT/UPDATE/DELETE)
- Использовать составные индексы для множественных условий
- Рассматривать частичные индексы для фильтрованных данных
- Регулярно анализировать использование индексов

### Оптимизация JOIN операций

- Использовать индексы на колонках JOIN
- Выбирать правильный порядок таблиц в JOIN (меньшие таблицы первыми)
- Избегать CROSS JOIN без необходимости
- Использовать INNER JOIN вместо OUTER JOIN, когда возможно

### Оптимизация WHERE условий

- Применять наиболее селективные условия первыми
- Использовать индексы для фильтрации
- Избегать функций в WHERE (например, `WHERE UPPER(name) = 'VALUE'`)
- Использовать параметризованные запросы вместо строковых конкатенаций

### Оптимизация агрегаций

- Использовать индексы для GROUP BY колонок
- Применять HAVING только когда необходимо (после GROUP BY)
- Рассматривать материализованные представления для сложных агрегаций

### Оптимизация подзапросов

- Преобразовывать коррелированные подзапросы в JOIN, когда возможно
- Использовать EXISTS вместо IN для проверки существования
- Рассматривать CTE для улучшения читаемости и производительности

### Кэширование и материализация

- Использовать материализованные представления для часто используемых запросов
- Настраивать кэш запросов на уровне приложения
- Рассматривать денормализацию для критичных по производительности запросов

### Анализ статистики

- Регулярно обновлять статистику таблиц (ANALYZE в PostgreSQL, ANALYZE TABLE в MySQL)
- Настраивать автообновление статистики
- Проверять точность статистики для больших таблиц

## Общие рекомендации

- Избегать SELECT * — выбирать только необходимые колонки
- Использовать LIMIT для ограничения результатов
- Применять пагинацию для больших наборов данных
- Мониторить медленные запросы через логи
- Использовать EXPLAIN для анализа планов выполнения
