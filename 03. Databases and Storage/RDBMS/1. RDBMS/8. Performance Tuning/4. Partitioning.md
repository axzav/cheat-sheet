# Партиционирование (Partitioning)

Партиционирование — разделение большой таблицы на меньшие, более управляемые части, называемые партициями. Каждая партиция может храниться и управляться независимо.

## Преимущества

1. **Производительность**: Запросы могут сканировать только релевантные партиции
2. **Обслуживание**: Операции над отдельными партициями выполняются быстрее
3. **Хранилище**: Можно хранить партиции на разных носителях
4. **Оптимизация запросов**: Partition pruning исключает нерелевантные партиции

## Типы партиционирования

### Range Partitioning (Партиционирование по диапазонам)

Партиции на основе диапазона значений.

**PostgreSQL:**
```sql
CREATE TABLE sales (
    id INT,
    sale_date DATE,
    amount DECIMAL
) PARTITION BY RANGE (sale_date);

CREATE TABLE sales_2023 PARTITION OF sales
    FOR VALUES FROM ('2023-01-01') TO ('2024-01-01');

CREATE TABLE sales_2024 PARTITION OF sales
    FOR VALUES FROM ('2024-01-01') TO ('2025-01-01');
```

**MySQL:**
```sql
CREATE TABLE sales (
    id INT,
    sale_date DATE,
    amount DECIMAL
) PARTITION BY RANGE (YEAR(sale_date)) (
    PARTITION p2023 VALUES LESS THAN (2024),
    PARTITION p2024 VALUES LESS THAN (2025),
    PARTITION p2025 VALUES LESS THAN (2026)
);
```

### List Partitioning (Партиционирование по списку)

Партиции на основе конкретных значений.

**PostgreSQL:**
```sql
CREATE TABLE users (
    id INT,
    country VARCHAR(2),
    name VARCHAR(100)
) PARTITION BY LIST (country);

CREATE TABLE users_us PARTITION OF users
    FOR VALUES IN ('US', 'CA', 'MX');

CREATE TABLE users_eu PARTITION OF users
    FOR VALUES IN ('GB', 'FR', 'DE');
```

**MySQL:**
```sql
CREATE TABLE users (
    id INT,
    country VARCHAR(2),
    name VARCHAR(100)
) PARTITION BY LIST COLUMNS (country) (
    PARTITION p_us VALUES IN ('US', 'CA', 'MX'),
    PARTITION p_eu VALUES IN ('GB', 'FR', 'DE')
);
```

### Hash Partitioning (Партиционирование по хэшу)

Партиции на основе хэш-функции.

**PostgreSQL:**
```sql
CREATE TABLE orders (
    id INT,
    user_id INT,
    order_date DATE
) PARTITION BY HASH (user_id);

CREATE TABLE orders_0 PARTITION OF orders;
CREATE TABLE orders_1 PARTITION OF orders;
CREATE TABLE orders_2 PARTITION OF orders;
CREATE TABLE orders_3 PARTITION OF orders;
```

**MySQL:**
```sql
CREATE TABLE orders (
    id INT,
    user_id INT,
    order_date DATE
) PARTITION BY HASH (user_id)
PARTITIONS 4;
```

### Composite Partitioning (Композитное партиционирование)

Комбинация нескольких стратегий партиционирования.

**PostgreSQL:**
```sql
CREATE TABLE sales (
    id INT,
    region VARCHAR(10),
    sale_date DATE,
    amount DECIMAL
) PARTITION BY LIST (region);

CREATE TABLE sales_us PARTITION OF sales
    FOR VALUES IN ('US')
    PARTITION BY RANGE (sale_date);

CREATE TABLE sales_us_2023 PARTITION OF sales_us
    FOR VALUES FROM ('2023-01-01') TO ('2024-01-01');
```

## Управление партициями

### Добавление партиций

**PostgreSQL:**
```sql
CREATE TABLE sales_2025 PARTITION OF sales
    FOR VALUES FROM ('2025-01-01') TO ('2026-01-01');
```

**MySQL:**
```sql
ALTER TABLE sales ADD PARTITION (
    PARTITION p2025 VALUES LESS THAN (2026)
);
```

### Удаление партиций

**PostgreSQL:**
```sql
DROP TABLE sales_2023;  -- Удаляет партицию
```

**MySQL:**
```sql
ALTER TABLE sales DROP PARTITION p2023;
```

### Объединение партиций

**MySQL:**
```sql
ALTER TABLE sales
    REORGANIZE PARTITION p2023, p2024 INTO (
        PARTITION p2023_2024 VALUES LESS THAN (2025)
    );
```

## Partition Pruning

База данных автоматически исключает партиции, которые не содержат релевантных данных:

```sql
-- Сканирует только партицию sales_2024
SELECT * FROM sales WHERE sale_date = '2024-06-15';

-- Сканирует все партиции (нет pruning)
SELECT * FROM sales WHERE amount > 1000;
```

## Best Practices

1. **Выбрать правильный ключ**: Партиционировать по часто используемой в запросах колонке
2. **Сбалансировать размер**: Поддерживать примерно равный размер партиций
3. **Ограничить количество**: Слишком много партиций может ухудшить производительность
4. **Индексы**: Создавать индексы на ключе партиционирования
5. **Обслуживание**: Планировать добавление/удаление партиций
6. **Запросы**: Проектировать запросы для включения partition pruning
7. **Мониторинг**: Отслеживать размеры и использование партиций

## Когда использовать партиционирование

- **Большие таблицы**: Таблицы с миллионами/миллиардами строк
- **Временные ряды**: Данные, естественно организованные по времени
- **Географические данные**: Данные, организованные по регионам
- **Архивирование**: Легко удалять старые партиции
- **Параллельные операции**: Операции могут выполняться параллельно

## Когда не использовать партиционирование

- Маленькие таблицы (< 1GB)
- Таблицы без четкого ключа партиционирования
- Частые cross-partition запросы
- Сложные JOIN между партициями
- Ограниченное окно обслуживания

## Партиционирование vs Шардирование

- **Партиционирование**: Одна база данных, логическое разделение
- **Шардирование**: Несколько баз данных, физическое разделение
- Использовать партиционирование для оптимизации на одном сервере
- Использовать шардирование для горизонтального масштабирования между серверами
