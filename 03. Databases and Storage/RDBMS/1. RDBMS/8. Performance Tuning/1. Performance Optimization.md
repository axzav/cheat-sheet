# Оптимизация производительности (Performance Optimization)

Оптимизация производительности базы данных включает настройку запросов, индексов, кэширования и партиционирования для улучшения скорости выполнения операций.

## Оптимизация запросов (Query Optimization)

### Анализ плана выполнения (EXPLAIN)

Использовать EXPLAIN для анализа плана выполнения запросов:

```sql
-- PostgreSQL
EXPLAIN ANALYZE SELECT * FROM users WHERE email = 'test@example.com';

-- MySQL
EXPLAIN SELECT * FROM users WHERE email = 'test@example.com';
```

### Основные принципы оптимизации запросов

1. **Использовать индексы**: Создавать индексы на часто используемых колонках в WHERE, JOIN, ORDER BY
2. **Избегать SELECT ***: Выбирать только необходимые колонки
3. **Использовать LIMIT**: Ограничивать количество возвращаемых строк
4. **Оптимизировать JOIN**: Использовать правильные типы JOIN и порядок таблиц
5. **Избегать подзапросов где возможно**: Использовать JOIN вместо подзапросов
6. **Использовать EXISTS вместо IN**: Для больших наборов данных
7. **Избегать функций в WHERE**: Не использовать функции на индексированных колонках

## Настройка индексов (Index Tuning)

### Типы индексов

- **B-tree**: Стандартный индекс, подходит для большинства случаев
- **Hash**: Быстрый поиск по равенству, только для PostgreSQL
- **GIN (Generalized Inverted Index)**: Для полнотекстового поиска, массивов
- **GiST (Generalized Search Tree)**: Для геоданных, полнотекстового поиска
- **BRIN (Block Range Index)**: Для больших таблиц с упорядоченными данными

### Создание индексов

```sql
-- Простой индекс
CREATE INDEX idx_email ON users(email);

-- Составной индекс
CREATE INDEX idx_name_email ON users(last_name, first_name);

-- Уникальный индекс
CREATE UNIQUE INDEX idx_unique_email ON users(email);

-- Частичный индекс (PostgreSQL)
CREATE INDEX idx_active_users ON users(email) WHERE status = 'active';
```

### Мониторинг использования индексов

```sql
-- PostgreSQL
SELECT * FROM pg_stat_user_indexes;

-- MySQL
SHOW INDEX FROM table_name;
```

## Настройка кэширования (Caching)

Кэширование позволяет хранить часто используемые данные в памяти для быстрого доступа.

### Кэширование на уровне базы данных

- **Buffer Pool**: Кэш страниц данных в памяти
- **Query Cache**: Кэш результатов запросов (устарело в MySQL 8.0)
- **Connection Pooling**: Переиспользование соединений

### Настройка Buffer Pool

```sql
-- PostgreSQL (shared_buffers в postgresql.conf)
shared_buffers = 256MB

-- MySQL (innodb_buffer_pool_size в my.cnf)
innodb_buffer_pool_size = 1G
```

## Партиционирование (Partitioning)

Партиционирование — разбиение одной большой таблицы на несколько таблиц, данные в которых попадают согласно установленным критериям. Все эти таблицы хранятся на одном сервере.

**Пример использования**: Новостные сайты. Имеет смысл хранить свежие новости в одной таблице, а архив старых новостей в другой таблице/таблицах. Так как количество запросов на свежие новости будет выше, чем на старые, выборка по маленькой таблице будет работать быстрее, чем по всему архиву новостей.

Подробнее см. раздел "Partitioning".

## Шардирование (Sharding)

Шардирование — горизонтальное разделение данных между несколькими базами данных на разных серверах.

**Отличие от партиционирования**: Партиционирование происходит на одном сервере, шардирование — на нескольких серверах.

Подробнее см. раздел "Sharding".

## Мониторинг производительности

### Ключевые метрики

- **Query execution time**: Время выполнения запросов
- **Throughput**: Количество запросов в секунду
- **Connection count**: Количество активных соединений
- **Cache hit ratio**: Процент попаданий в кэш
- **Disk I/O**: Операции чтения/записи на диск

### Инструменты мониторинга

- **pg_stat_statements** (PostgreSQL): Статистика выполнения запросов
- **Performance Schema** (MySQL): Детальная статистика производительности
- **pgAdmin, phpMyAdmin**: Графические инструменты мониторинга
- **Prometheus + Grafana**: Внешние системы мониторинга

## Best Practices

1. Регулярно анализировать медленные запросы
2. Мониторить использование индексов
3. Настраивать размеры кэшей в зависимости от доступной памяти
4. Использовать connection pooling
5. Планировать регулярное обслуживание (VACUUM, ANALYZE)
6. Документировать изменения в конфигурации
7. Тестировать изменения производительности на тестовой среде
