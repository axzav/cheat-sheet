# Транзакции (Transactions)

Транзакции обеспечивают, что серия операций с базой данных либо выполняется полностью, либо не выполняется вовсе, поддерживая целостность данных.

## Базовый синтаксис

### PostgreSQL / MySQL

```sql
BEGIN;  -- или START TRANSACTION;
-- SQL-операторы
COMMIT;  -- или ROLLBACK;
```

### Автоматическая фиксация

По умолчанию каждый оператор автоматически фиксируется. Использовать транзакции для группировки нескольких операторов.

## Свойства транзакций (ACID)

- **Atomicity** (Атомарность) — все или ничего. Либо все операции выполняются, либо ни одна
- **Consistency** (Согласованность) — база данных остается в валидном состоянии
- **Isolation** (Изолированность) — параллельные транзакции не мешают друг другу
- **Durability** (Долговечность) — зафиксированные изменения сохраняются

## Управление транзакциями

### COMMIT

Сохраняет все изменения в транзакции:

```sql
BEGIN;
INSERT INTO users (username, email) VALUES ('user1', 'user1@example.com');
UPDATE accounts SET balance = balance - 100 WHERE user_id = 1;
COMMIT;  -- сохранить все изменения
```

### ROLLBACK

Отменяет все изменения в транзакции:

```sql
BEGIN;
INSERT INTO users (username, email) VALUES ('user2', 'user2@example.com');
-- что-то пошло не так
ROLLBACK;  -- отменить все изменения
```

### Точки сохранения (Savepoints)

Позволяют откатываться к определенной точке внутри транзакции:

```sql
BEGIN;
-- выполнение операций
SAVEPOINT sp1;
-- выполнение дополнительных операций
ROLLBACK TO SAVEPOINT sp1;  -- откат к точке сохранения
-- продолжение или
COMMIT;
```

### Пример с точками сохранения

```sql
BEGIN;
INSERT INTO orders (user_id, total) VALUES (1, 100);

SAVEPOINT before_items;
INSERT INTO order_items (order_id, product_id, quantity) 
VALUES (1, 10, 2);

-- Если что-то пошло не так с позициями
ROLLBACK TO SAVEPOINT before_items;

-- Продолжить с другими позициями
INSERT INTO order_items (order_id, product_id, quantity) 
VALUES (1, 20, 1);

COMMIT;
```

## Уровни изоляции транзакций

Уровни изоляции определяют, как транзакции взаимодействуют друг с другом при параллельном выполнении.

### Установка уровня изоляции

```sql
-- PostgreSQL
SET TRANSACTION ISOLATION LEVEL READ COMMITTED;

-- MySQL
SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED;
```

### Основные уровни изоляции

1. **READ UNCOMMITTED** — самый низкий уровень, возможны "грязные" чтения
2. **READ COMMITTED** — чтение только зафиксированных данных (по умолчанию в PostgreSQL)
3. **REPEATABLE READ** — повторяемое чтение (по умолчанию в MySQL)
4. **SERIALIZABLE** — самый высокий уровень, полная изоляция

## Вложенные транзакции

Большинство баз данных не поддерживают истинно вложенные транзакции, но точки сохранения (savepoints) предоставляют похожую функциональность.

## Примеры использования

### Перевод денег между счетами

```sql
BEGIN;
UPDATE accounts SET balance = balance - 100 WHERE id = 1;
UPDATE accounts SET balance = balance + 100 WHERE id = 2;
COMMIT;
```

### С обработкой ошибок

```sql
BEGIN;
BEGIN
    UPDATE accounts SET balance = balance - 100 WHERE id = 1;
    UPDATE accounts SET balance = balance + 100 WHERE id = 2;
    COMMIT;
EXCEPTION
    WHEN OTHERS THEN
        ROLLBACK;
        RAISE;
END;
```

### Пакетная вставка с откатом при ошибке

```sql
BEGIN;
INSERT INTO users (username, email) VALUES 
    ('user1', 'user1@example.com'),
    ('user2', 'user2@example.com'),
    ('user3', 'user3@example.com');

-- Если любая вставка не удалась, откатить все
COMMIT;
```

## Рекомендации

**Держать транзакции короткими**: Длительные транзакции блокируют ресурсы и могут привести к дедлокам.
**Не держать блокировки без необходимости**: Освобождать блокировки как можно скорее.
**Правильно обрабатывать ошибки**: Всегда проверять результат операций и выполнять ROLLBACK при ошибках.
**Использовать подходящий уровень изоляции**: Выбирать минимально необходимый уровень изоляции для баланса между целостностью и производительностью.
**Избегать длительных транзакций**: Длительные транзакции увеличивают риск конфликтов и снижают производительность.
**Тестировать сценарии отката**: Убедиться, что приложение корректно обрабатывает откаты транзакций.

## Распространенные проблемы

**Дедлоки (Deadlocks)**: Когда две транзакции блокируют друг друга. Решение: использовать таймауты и правильный порядок блокировок.
**Потерянные обновления (Lost Updates)**: Когда два обновления перезаписывают друг друга. Решение: использовать подходящий уровень изоляции.
**Фантомные чтения (Phantom Reads)**: Когда в транзакции появляются новые строки, добавленные другой транзакцией. Решение: использовать SERIALIZABLE или блокировки диапазонов.
