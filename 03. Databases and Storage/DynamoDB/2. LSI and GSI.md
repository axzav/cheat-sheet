# LSI and GSI

В **Amazon DynamoDB** используется 2 типа индексов:


##  LSI — Local Secondary Index

Local Secondary Indexes still rely on the original Hash Key. When you supply a table with hash+range, think about the LSI as hash+range1, hash+range2.. hash+range6. You get 5 more range attributes to query on. Also, there is only one provisioned throughput.

* Привязан к **той же partition key**, что и основная таблица.
* Позволяет **индексировать по другому sort key**.
* **Создаётся только при создании таблицы**, изменить или добавить LSI позже **невозможно**.
* Делит **тот же throughput** и **хранение** с основной таблицей.
* Максимум **5 LSI на таблицу**.
* Используется редко, поскольку гибкость ограничена.

**Пример:**

Если у тебя таблица с:

```plaintext
partition key: user_id
sort key: timestamp
```

LSI можно создать с другим sort key, например `status`.

---

##  GSI — Global Secondary Index

Global Secondary Indexes defines a new paradigm - different hash/range keys per index.
This breaks the original usage of one hash key per table. This is also why when defining GSI you are required to add a provisioned throughput per index and pay for it.

* Может иметь **другие partition и sort key**, не совпадающие с основной таблицей.
* **Создаётся в любое время**, после создания таблицы.
* Использует **собственный throughput и storage** (если в on-demand — это не сильно важно).
* Гибкий и мощный инструмент для альтернативных запросов.
* Максимум **20 GSI на таблицу** (можно запросить повышение лимита).

**Пример:**

Можно создать GSI по:

```plaintext
partition key: email
sort key: signup_date
```

чтобы находить пользователей по email независимо от основного ключа.

---

## Что чаще используется?

На практике почти **все современные дизайны используют GSI**, потому что:

* Их можно создавать и удалять динамически.
* Они не ограничены partition key основной таблицы.
* Более гибкие под рост и изменения схемы.

LSI используют **редко**, и только если:

* Точно известна нужда во вторичном sort key при создании таблицы.
* Нужно экономить на storage (LSI не дублирует данные как GSI).

LSI используются только в очень специфических случаях.
