Иммутабельный объект — это объект, состояние которого нельзя изменить после его создания. Это означает, что ни одно из свойств объекта не может быть изменено после того, как он был инициализирован. Всякий раз, когда необходимо изменить состояние иммутабельного объекта, вместо изменения текущего объекта создается новый объект с новым состоянием.

Преимущества

1️⃣Безопасность и предсказуемость:
✅Иммутабельные объекты безопасны для использования в многопоточных средах, так как их состояние не может быть изменено после создания, что предотвращает состояние гонки и другие проблемы, связанные с конкурентным доступом.

2️⃣Простота понимания и отладки:
✅Так как состояние иммутабельного объекта не изменяется, код, использующий такие объекты, становится более предсказуемым и легче в отладке.

3️⃣Облегчение управления состоянием:
✅Иммутабельные объекты упрощают управление состоянием в приложениях, так как можно быть уверенным, что состояние объекта не изменится неожиданным образом.

4️⃣Безопасность при передаче данных:
✅Иммутабельные объекты могут безопасно передаваться между различными частями программы или даже между разными системами, так как нет риска, что их состояние будет изменено в процессе передачи.

Примеры иммутабельных объектов

Строки и кортежи являются примерами встроенных иммутабельных объектов.
```python
# Строки являются иммутабельными
s = "hello"
# Любая операция, изменяющая строку, создает новую строку
s = s.upper()
print(s)  # Выведет "HELLO"

# Кортежи также являются иммутабельными
t = (1, 2, 3)
# Попытка изменить элемент кортежа вызовет ошибку
# t[0] = 0  # TypeError: 'tuple' object does not support item assignment
```

Класс String является иммутабельным. Всякий раз, когда выполняется операция, изменяющая строку, создается новый объект строки.
```python
String s = "hello";
s = s.toUpperCase();
System.out.println(s);  // Выведет "HELLO"
```

Для создания своих иммутабельных классов в Java можно сделать следующее:
1️⃣Сделать класс финальным, чтобы предотвратить наследование.
2️⃣Все поля объявить приватными и финальными.
3️⃣Не предоставлять методов для изменения состояния (сеттеров).
4️⃣Обеспечить, чтобы изменяемые объекты, передаваемые в конструктор, были скопированы.

```java
public final class ImmutablePerson {
    private final String name;
    private final int age;

    public ImmutablePerson(String name, int age) {
        this.name = name;
        this.age = age;
    }

    public String getName() {
        return name;
    }

    public int getAge() {
        return age;
    }
}
```

Для создания иммутабельных объектов необходимо соблюдать несколько правил:

1️⃣Приватные и финальные поля: Все поля объекта должны быть объявлены как private и final.
2️⃣Отсутствие сеттеров: Не должны быть предоставлены методы, которые позволяют изменять состояние объекта.
3️⃣Конструкторы: Конструкторы должны устанавливать все поля объекта, инициализируя их значениями, которые не могут быть изменены после создания объекта.
4️⃣Защита изменяемых объектов: Если объект содержит изменяемые поля, такие как массивы или коллекции, они должны быть скопированы или защищены от изменения извне.

Иммутабельные объекты — это важная концепция, которая помогает создавать безопасный и предсказуемый код. Они особенно полезны в многопоточных средах и при передаче данных между различными частями системы. Создание иммутабельных объектов требует соблюдения определенных правил, но это приносит значительные преимущества в плане безопасности и управляемости кода.


Иммутабельность и чистота функций тесно связаны в контексте функционального программирования, и их связь можно объяснить через принципы, которые они обеспечивают.

Иммутабельность 

Означает, что объект или структура данных не может быть изменена после создания. Все операции, которые изменяют иммутабельный объект, создают новый объект с новым состоянием, оставляя оригинальный объект неизменным.

Чистая функция

Это функция, которая удовлетворяет двум основным условиям:
1️⃣Детерминированность: Возвращает одно и то же значение для одних и тех же входных данных.
2️⃣Отсутствие побочных эффектов: Не изменяет состояние программы и не зависит от внешнего состояния, за исключением своих входных параметров.

Связь между иммутабельностью и чистотой

1️⃣Отсутствие побочных эффектов:
✅Иммутабельные объекты способствуют созданию чистых функций, так как изменение состояния объектов не приводит к изменению внешнего состояния программы. Это гарантирует, что функции не будут иметь побочных эффектов, поскольку иммутабельные объекты не изменяются после создания.

2️⃣Детерминированность:
✅Использование иммутабельных объектов в чистых функциях способствует детерминированности. Поскольку иммутабельные объекты не меняются, функции, работающие с ними, всегда будут возвращать одно и то же значение для одних и тех же входных данных.

```python
def add(a, b):
    return a + b

result1 = add(2, 3)  # Всегда возвращает 5
result2 = add(2, 3)  # Всегда возвращает 5
```

В этом примере функция add является чистой, так как она детерминирована и не имеет побочных эффектов.

Пример на Python
```python
from typing import NamedTuple

class Point(NamedTuple):
    x: int
    y: int

p1 = Point(1, 2)
p2 = p1._replace(x=3)

print(p1)  # Point(x=1, y=2)
print(p2)  # Point(x=3, y=2)
```

В этом примере Point является иммутабельным объектом. Метод _replace создает новый объект, вместо изменения состояния существующего объекта.

Практическое значение

1️⃣Предсказуемость и надежность:
✅Иммутабельность и чистота делают код предсказуемым и легким для понимания, тестирования и отладки. Если функции детерминированы и не имеют побочных эффектов, поведение программы становится более предсказуемым.

2️⃣Безопасность в многопоточной среде:
✅В многопоточных приложениях иммутабельные объекты и чистые функции уменьшают риски состояния гонки и других проблем, связанных с конкурентным доступом к данным.

3️⃣Простота тестирования:
✅Чистые функции легко тестировать, так как для одного набора входных данных всегда получается один и тот же результат. Это устраняет необходимость сложных тестовых окружений для проверки побочных эффектов.

Иммутабельность и чистота функций тесно связаны, так как такие объекты способствуют созданию чистых функций. Использование этих принципов повышает предсказуемость, надежность и тестируемость кода, а также улучшает безопасность в многопоточных средах.
