# Dockerfile

**Dockerfile** это файл манифеста, который служит для создания образов.

```docker
FROM ubuntu:18.04

COPY . /app

RUN make /app
RUN make /test

ENTRYPOINT ["python"]
CMD ["/app/app.py"]
```

Dockerfile состоит из следующих компонентов:
- Базовый образ (`FROM`)
- Описание образа (`LABEL`)
- Команды (`RUN`)
- Рабочие директории (`WORKDIR`)
- Файлы (`COPY`, `ADD`)
- Работа с файлами (`RUN`)
- Переменные окружения (`ENV`)
- Порты (`EXPOSE`)
- Описание команд при запуске контейнера (`ENTRYPOINT`, `CMD`)


## ENTRYPOINT and CMD

```dockerfile
ENTRYPOINT ["nginx"]
CMD ["-g", "daemon off;"]
```

```shell
nginx -g "daemon off;"  # ENTRYPOINT + CMD
```

* **ENTRYPOINT** - основной процесс контейнера
* **CMD** - аргументы запуска основного процесса

Если в `Dockerfile` не были указаны `CMD` и `ENTRYPOINT`, то контейнер сразу же завершится - no command specified.

**CMD** легко перезаписывается при запуске контейнера, например:
```shell
ENTRYPOINT ["echo"]
CMD ["Hello Docker"]
```

```shell
docker run test_img            # Выведет "Hello Docker"
docker run test_img hello_run  # Выведет "hello_run"
```

**ENTRYPOINT** можно переопределить при запуске контейнера:
```shell
docker run --entrypoint bash nginx
```

**ENTRYPOINT + CMD = лучший паттерн**. Позволяет делать такие вещи:
```dockerfile
ENTRYPOINT ["node"]
CMD ["app.js"]
```

```shell
docker run image            # default: node app.js
docker run image other.js   # node other.js
```

**Антипаттерн:**
```dockerfile
ENTRYPOINT ["node", "app.js"]
```


## RUN

**RUN** - выполнить команду во время билда образа


## COPY

**COPY** - копирует файлы с хост машины в контейнер. Например, можно скопировать какой-то бинарник внутрь контейнера или файлы веб-приложения для продакшена. Тут есть какой-то кеш.
Если скопировать файлы проекта в контейнер `COPY . .` то когда они изменятся при билде проекта, придется выполнять слой заранее. Реальный кейс: допустим в докерфайле копируется веб приложение и затем выполнятся **composer install**. Тогда если файлы проекта поменялись, то при билде этап копирования и установки зависимостей повторится. Но если сначала скопировать только `composer.lock/json` и выполнить **composer install** то если зависимости не поменялись, то слой с их установкой закешируется и не будет выполняться повторно.


## WORKDIR

`WORKDIR` - 2 применения. **COPY** будет копировать файлы сразу в WORKDIR и при подключении к контейнеру терминал сразу будет открыт в WORKDIR.


## EXPOSE

`EXPOSE 80/tcp` - expose используется для информационных целей (в inspect и ps). Если его не указать в докерфайле то все равно все будет работать


## ENV

**ENV** - указание переменных окружения. docker run -e перепишет переменные указанные в докерфайле, однако только после запуска контейнера, т.е. до момента полного запуска контейнера переменная окружения будет иметь старое значение. Что логично, т.к. образ уже был сбилжен ранее именно с переменной в ENV и эта информация записана с слоях. Но если операции происходят в слое контейнера (CMD, ENTRYPOINT?), то переменные окружения будут браться из docker run -e

## VOLUME

VOLUME в Dockerfile и volumes в docker-compose.yml имеют разные цели. 
VOLUME в Dockerfile обычно используется для создания томов, которые могут быть использованы другими контейнерами, или для сохранения данных вне контейнера. 
volumes в docker-compose.yml обычно используется для монтирования директорий на хосте в контейнер, что особенно полезно во время разработки для обмена файлами между хостом и контейнером.


## Other

**LABEL** - метаинформация

**USER** - указывает пользователя, от имени которого будет выполниться корневой процесс в докере.

**ARG** - позволяет устанавливать аргументы в докерфайле, которые затем можно в нем же и использовать. Также можно указать аргумент при сборке и переопределить тот который был указан в докерфайле. Кроме этого это позволяет передавать аргументы в рантайме без "запекания" их в контейнере (как это происходит при использовании **ENV**), что также полезно с точки зрения безопасности. ARG доступен только при старте в рантайме.
```sh
docker build --build-arg image=busybox
```
