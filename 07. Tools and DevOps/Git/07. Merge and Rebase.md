# Merge и Rebase

Оба метода используются для интеграции изменений из одной ветки в другую, но делают это по-разному.

## Merge

Объединяет изменения из одной ветки в другую, создавая merge-коммит с двумя родителями.

### Особенности

- ✅ Не изменяет историю — сохраняет полную историю проекта
- ✅ Создает merge-коммит — может загромождать историю в больших проектах
- ✅ Безопасен для публичных веток

### Использование

```shell
git checkout main
git merge feature-branch
```

## Rebase

Переносит коммиты из одной ветки поверх другой, переписывая историю для создания линейной последовательности.

### Особенности

- ✅ Создает линейную историю — без merge-коммитов
- ✅ Изменяет историю — переписывает коммиты
- ⚠️ Рискован для опубликованных веток — может вызвать проблемы у других разработчиков

### Использование

```shell
git checkout feature-branch
git rebase main
```

## Когда использовать

### Используйте Merge, если:

- Важна точная история изменений
- Работаете в команде с регулярной синхронизацией
- Ветка уже опубликована и используется другими

### Используйте Rebase, если:

- Хотите поддерживать чистую линейную историю
- Работаете с локальной веткой перед вливанием в основную
- Готовы переписать историю (только для локальных веток)

## Интерактивный rebase

Для изменения нескольких коммитов:

```shell
git rebase -i HEAD~<количество_коммитов>
```

Доступные операции:
- `pick` — использовать коммит как есть
- `reword` — изменить сообщение коммита
- `edit` — остановиться для редактирования
- `squash` — объединить с предыдущим коммитом
- `drop` — удалить коммит
