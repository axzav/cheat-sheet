# Conventional Commits

Стандарт формата сообщений коммитов для автоматической генерации changelog и определения версий.

## Формат

```
<type>[optional scope]: <description>

[optional body]

[optional footer(s)]
```

## Типы коммитов

| Тип | Назначение | Пример |
|-----|------------|--------|
| `feat` | Добавление новой функциональности | `feat: добавить авторизацию через OAuth` |
| `fix` | Исправление бага | `fix: исправить падение при сохранении пустого поля` |
| `docs` | Изменения в документации | `docs: обновить README` |
| `style` | Изменения форматирования (без изменения логики) | `style: привести код к стандарту ESLint` |
| `refactor` | Рефакторинг (без новой функциональности и багфиксов) | `refactor: упростить структуру компонента` |
| `test` | Добавление/изменение тестов | `test: добавить unit-тесты для auth модуля` |
| `chore` | Поддерживающие изменения, не влияющие на код | `chore: обновить зависимости npm` |

## Примеры

### Простые коммиты

```bash
feat: добавить поддержку темной темы
fix: исправить утечку памяти в компоненте
docs: обновить инструкцию по установке
```

### С указанием области (scope)

```bash
feat(auth): добавить двухфакторную аутентификацию
fix(ui): исправить отображение кнопки на мобильных устройствах
fix(test): неправильно настроен мок API в unit-тестах
```

### Chore

Используется для изменений, не затрагивающих исходный код приложения или тестов:

```bash
chore: обновить зависимости npm
chore: добавить настройку Prettier
chore: обновить GitHub Actions workflow
chore: поправить README
```

## Преимущества

- Автоматическая генерация changelog
- Автоматическое определение версий (semver)
- Улучшенная читаемость истории коммитов
- Легче найти нужные изменения в истории
