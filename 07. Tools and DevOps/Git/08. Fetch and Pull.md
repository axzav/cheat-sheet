# Fetch и Pull

Обе команды синхронизируют локальный репозиторий с удаленным, но делают это по-разному.

## Fetch

Загружает изменения из удаленного репозитория, но **не вносит их в текущую рабочую ветку**.

### Использование

```shell
git fetch origin
```

### Когда использовать

- Хотите увидеть изменения перед интеграцией
- Нужен контроль над процессом объединения
- Работаете с несколькими ветками

### Просмотр изменений после fetch

```shell
# Просмотреть коммиты в удаленной ветке
git log origin/main

# Сравнить с локальной веткой
git diff main origin/main

# Внести изменения в текущую ветку
git merge origin/main
```

## Pull

Выполняет `git fetch` и затем автоматически объединяет (merge) загруженные изменения с текущей веткой.

### Использование

```shell
git pull origin main
```

### Когда использовать

- Хотите быстро получить и применить изменения
- Уверены, что конфликтов не будет
- Работаете в одиночку или в небольшой команде

## Сравнение

| Команда | Что делает | Контроль | Автоматизация |
|---------|------------|----------|---------------|
| `fetch` | Загружает изменения | ✅ Полный контроль | Требует ручного merge |
| `pull` | Загружает и объединяет | ⚠️ Меньше контроля | Автоматический merge |

## Рекомендации

Для большей безопасности и контроля используйте:

```shell
# 1. Сначала получить изменения
git fetch origin

# 2. Просмотреть что изменилось
git log HEAD..origin/main

# 3. Затем объединить
git merge origin/main
```

Это дает возможность просмотреть изменения перед их применением.
