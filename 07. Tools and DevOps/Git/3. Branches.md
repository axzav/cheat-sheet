# Branches

Что такое ветка в Git

Ветка — это просто указатель на коммит.

Не папка.
Не копия проекта.
Не отдельная сущность.

Это literally pointer на последний коммит в цепочке.

Когда ты делаешь новый коммит — ветка просто “сдвигается” вперёд.


```shell
git branch --show-current
```

git branch : Покажет локальные ветки.
git branch -a : локальные и удалённые (remote-tracking)
git branch -r : Только удалённые.

git branch feature/login : Создаёт ветку, но не переключает на неё.
git checkout -b feature/login - Создать и сразу переключиться
git switch -c feature/login - Создать и сразу переключиться

git checkout branch-name : Переключиться на ветку
git switch branch-name : Переключиться на ветку

git branch -d feature/login : Удалить ветку, Удалит только если ветка слита (merged).
git branch -D feature/login : git branch -D feature/login

git push origin feat/CTI-995-update-auth : пушить ветку
git push -u origin feat/CTI-995-update-auth : -u = установить upstream

Это значит:

Git запомнит связь.
Потом можно просто писать git push и git pull

Что такое upstream
локальная ветка → удалённая ветка
git branch -vv : Посмотреть

Форс пуш
```shell
git push origin HEAD --force
```

В системе управления версиями Git команды pull и fetch используются для синхронизации локального репозитория с удаленным репозиторием, но делают они это по-разному.

Основные различия между ними

git fetch

✅Что делает: Команда загружает изменения из удаленного репозитория в ваш локальный репозиторий, но не вносит их в текущую рабочую ветку.
✅Использование: Это полезно, когда вы хотите увидеть все изменения, которые произошли в удаленном репозитории, прежде чем интегрировать их в свою работу.

```shell
git fetch origin
```

Эта команда скачает все обновления из удаленного репозитория с именем origin, но ваша текущая ветка останется неизменной. После этого вы можете просмотреть изменения, используя команды, такие как git log или git diff.

git pull

✅Что делает: Команда выполняет git fetch и затем автоматически объединяет (merge) загруженные изменения с вашей текущей веткой.
✅Использование: Удобно, когда вы хотите сразу получить последние изменения и объединить их с вашей текущей работой.

```shell
git pull origin main
```

Эта команда сначала скачает изменения из удаленной ветки main репозитория origin, а затем попытается автоматически объединить эти изменения с вашей текущей веткой.

Почему это важно
✅Контроль: Дает вам больше контроля над процессом интеграции изменений, так как позволяет сначала просмотреть изменения и решить, как их лучше внедрить.
✅Автоматизация: Удобен для быстрого обновления вашей работы, но автоматическое объединение может иногда привести к конфликтам, которые необходимо будет разрешать вручную.

Использование git fetch

1️⃣Скачайте изменения из удаленного репозитория:
```shell
git fetch origin
```

2️⃣Просмотрите изменения:
```shell
git log origin/main
```

3️⃣Внесите изменения в свою ветку:
```shell
git merge origin/main
```

Использование git pull

1️⃣Скачайте и объедините изменения в одну команду:
```shell
git pull origin main
```

git fetch загружает изменения из удаленного репозитория без автоматического объединения с вашей текущей веткой, тогда как git pull делает это объединение автоматически после загрузки изменений.

В чем разница между merge и rebase ?

merge и rebase являются двумя различными способами интеграции изменений из одной ветки в другую. Оба метода используются для слияния изменений, но они делают это по-разному и имеют различные последствия для истории коммитов.

merge

Используется для объединения изменений из одной ветки в другую. Merge создаёт новый коммит, который автоматически имеет двух родителей: один указывает на последний коммит текущей ветки (на которую вы сейчас нацелены), а другой — на коммит из сливаемой ветки.

Особенности:
✅Не изменяет историю. История сохраняется такой, какая она есть, что может быть полезно для сохранения полной истории проекта и контекста изменений.
✅Создаёт "merge commit". Этот коммит объединяет истории двух веток, что иногда может привести к загромождению истории, особенно в больших проектах с множеством веток.
git merge feature-branch
Эта команда объединит изменения из feature-branch в текущую ветку.

Rebase

Это другой способ интеграции изменений, который фактически переносит ветку на новую базу. При его использовании коммиты из одной ветки переносятся и применяются поверх другой ветки.

Особенности:
✅Изменяет историю. Переписывает историю коммитов, что делает её более чистой и линейной.
✅Избегает лишних merge commits. История коммитов выглядит как последовательный поток, что может облегчить понимание истории изменений.
✅Может быть рискованным. Изменение истории веток, которые уже были опубликованы и используются другими разработчиками, может привести к конфликтам и потребует от всех участников проекта пересинхронизировать свои репозитории.
git rebase master
Эта команда перенесёт текущую ветку на вершину ветки master.

Когда их использовать

✅Используйте merge, если вам важно сохранить точную историю изменений и когда работаете в команде, где изменения регулярно синхронизируются между множеством веток.
✅Используйте rebase, если вы хотите поддерживать чистую и линейную историю изменений, особенно перед вливанием локальной ветки в основную. Однако важно сначала получить последние изменения из основной ветки и только после этого выполнять rebase.

Выбор между merge и rebase может зависеть от конкретной ситуации и от того, какие приоритеты и политики установлены в вашем проекте относительно управления версиями.
