В системе **Conventional Commits** тег `chore` используется для коммитов, которые вносят **изменения в проект, не затрагивающие исходный код приложения или тестов** — то есть это «хозяйственные» изменения, не влияющие напрямую на функциональность.

### Примеры использования `chore`:

* Обновление зависимостей:

  ```
  chore: обновить зависимости npm
  ```
* Настройка инструментов сборки или линтеров:

  ```
  chore: добавить настройку Prettier
  ```
* Изменения в CI/CD пайплайне:

  ```
  chore: обновить GitHub Actions workflow
  ```
* Обновление документации, не относящейся к коду:

  ```
  chore: поправить README
  ```

### Отличие от других типов:

| Тип коммита | Назначение                                             |
| ----------- | ------------------------------------------------------ |
| `feat`      | Добавление новой фичи                                  |
| `fix`       | Исправление бага                                       |
| `docs`      | Изменения в документации                               |
| `style`     | Изменения в стиле (без изменения логики)               |
| `refactor`  | Рефакторинг (без новой функциональности и багфиксов)   |
| `test`      | Добавление/изменение тестов                            |
| `chore`     | Поддерживающие изменения, не влияющие на код или тесты |

Таким образом, `chore` — это просто способ отделить «обслуживающие» коммиты от логических изменений функциональности.


---

Конечно! Вот несколько примеров названий коммитов с типом `fix` в стиле **Conventional Commits**:

---

### 🔧 **Простой пример**

```
fix: исправить падение при сохранении пустого поля
```

---

### 🐛 **С указанием области**

```
fix(auth): устранить баг с повторной авторизацией
```

---

### 🧪 **Для бага, обнаруженного в тестах**

```
fix(test): неправильно настроен мок API в unit-тестах
```

---

### 🕵️ **Когда баг найден в UI**

```
fix(ui): кнопка выхода перекрывается текстом на мобильных устройствах
```

---

Если ты используешь semver + автогенерацию changelog'а (например, с `standard-version`), такие коммиты попадут в раздел `Bug Fixes` при генерации журнала изменений.
