# Cherry-pick

Cherry-pick позволяет применить один или несколько коммитов из другой ветки в текущую ветку.

## Основное использование

### 1. Переключиться на целевую ветку

```shell
git checkout <branch-name>
```

### 2. Найти хеш коммита

```shell
git log <source-branch>
```

### 3. Выполнить cherry-pick

Применить один коммит:

```shell
git cherry-pick <commit-hash>
```

Применить несколько коммитов:

```shell
git cherry-pick <commit-hash-1> <commit-hash-2>
```

Применить диапазон коммитов:

```shell
git cherry-pick <start-hash>..<end-hash>
```

## Разрешение конфликтов

Если возникли конфликты:

1. Разрешить конфликты вручную
2. Добавить разрешенные файлы:

```shell
git add .
```

3. Продолжить cherry-pick:

```shell
git cherry-pick --continue
```

4. Или отменить:

```shell
git cherry-pick --abort
```

## Важные замечания

- Cherry-pick создает **новый коммит** с теми же изменениями, что и оригинальный. Хеш коммита будет отличаться.
- Cherry-pick нужно делать на **обычные коммиты**, а не merge-коммиты. Merge-коммиты имеют двух родителей и могут вызвать проблемы.

## Пример: Hotfix из develop в main

```shell
# 1. Переключиться на main
git checkout main
git pull origin main

# 2. Найти хеш коммита с фиксом в develop
git log develop

# 3. Выполнить cherry-pick
git cherry-pick abc1234

# 4. Создать ветку для PR
git checkout -b hotfix/quick-fix-name
git push origin hotfix/quick-fix-name
```

При будущем merge `develop → main` Git автоматически распознает дубликат коммита и не создаст конфликт.
