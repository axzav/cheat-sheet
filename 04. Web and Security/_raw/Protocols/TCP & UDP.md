# TCP & UDP

 Протоколы транспортного уровня. 
 
- **TCP** - обеспечивает гарантию доставки пакета и порядка следования сообщений
- **UDP** - не гарантирует доставку данных, но работает быстрее TCP. Подходит для стриминга, видео и аудио потоков

## TCP (transmission control protocol)

Протокол обеспечивает гарантию доставки данных и сохранение порядка следования сообщений.

Транспортная подсистема получает от приложения данные в виде **потока байт**. Поток разбивается на **сегменты**.
Получатель объединяет сегменты и передает поток байт в приложение получателя

Процесс передачи данных в TCP:
- Установка соединения
- Передача данных
- Разрыв соединения

**Установка соединения**
![](../../../attachment/b329d2d7b73b424cf577e690e9e80c50.png)
Процесс установки TCP соединения еще называется трехкратным рукопожатием.
TCP соединение является дуплексным, т.е. оба хоста могут отправлять сегменты друг другу.

**Разрыв соединения**
![](../../../attachment/5425499692c68dc549eae729c226b2ae.png)

Корректное завершение производится отправкой сообщения **FIN** и получение ответа **ACK**
Т.к. соединение дуплексное, то разрыв соединения должен производится обоими хостами.
Если один хост разорвал соединение, но второй хост нет, то второй может продолжать отправлять сообщения через соединение.

Также существует закрытие соединения из-за критической ситуации с помощью сообщения **RST**. В таком случае соединение закрыватся для обоих хостов.

Если никакой сигнал на разрыв соединения не был отправлен, то соединение будет разорвано по таймауту

**Защита от потери сегментов**
![](../../../attachment/176a12591f2f64954a89ad26e440471b.png)
Получатель отправляет сообщение ACK отправителю в подтверждение, что сегмент получен
Если получатель не получил сообщение и не отправил ACK отправителю, то отправитель отправит сообщение еще раз. Такой вариант называется **остановка и ожидание**.

На практике чаще используется **механизм скользящего окна** - подтверждается получение не каждого сегмента, а нескольких сегментов отправленных друг за другом и в ответ получает кумулятивное подтверждение.

**Соблюдение порядка следования сообщений**
![](../../../attachment/96235d87e362f15b6c2d9aeed1d997a7.png)
Каждый сегмент нумеруется. После установления соединения хосты договорились о нумерации сегментов и получатель может легко восстановить поток байт из сегментов по нумерации.

## UDP (user datagram protocol)

Сообщение в UDP называется datagram.

Особенности UDP:
- Нет соединения
- Нет гарантии доставки данных
- Нет гарантии сохранения порядка сообщений
- Надежность по сравнению с IP не повышается
- Высокая скорость, т.к. нет соединения

Зачем нужен протокол UDP если он не вносит ничего нового по сравнению с протоколом IP? - на уровне протокола IP (сетевой) нет данных о порте. Формат заголовка сообщения UPD очень простой и как раз добавляет порт получаетеля

Формат заголовка UDP:
- Порт отправителя (16 бит)
- Порт получателя (16 бит)
- Длина UDP (16 бит)
- Контрольная сумма UDP (16 бит)

Длина UPD от 8 байт (только заголовок) до 65 515 байт (максимальная длина даных IP-пакета)

**Использование**: UDP используется тогда, когда нет необходимости в соединении между хостами и некоторая потеря данных не критична. Возникающие ошибки в передаче данных должно решать приложение.

Примеры использования:
- простое взаимодействие запрос-ответ, например запросы к DNS используют протокол UDP
- видео/аудио потоки
