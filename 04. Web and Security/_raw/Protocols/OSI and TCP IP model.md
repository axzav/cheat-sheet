Во время развития интернета параллельно развивались модель **OSI** и практически используемый стек технологий **TCP/IP**.
Сложилось так, что модель **OSI** не нашла широкого практического применения, а основной моделью в сети интернет стала модель **TCP/IP**

Модели описывают способы, стандарты и протоколы для передачи данных в компьютерных сетях. Описывают уровни и что на каждом уровне должно происходить

## Физический уровень

**Задача уровня:** как представить биты информации в виде сигналов, передаваемых по среде

Единица данных - **бит**

Технологии физического уровня:
- Медный кабель
- Оптический кабель
- Радиоволны

Основное сетевое оборудование - **коммутатор, точка доступа**

## Канальный уровень

**Основная задача уровня**: передача сообщений по каналам связи - кадров (frame)
Оборачивает во фрейм пакет из сетевого уровня.

Единица данных - **кадр/фрейм**

Формат кадра Ethernet:
- Адрес получателя (6 байт)
- Адрес отправителя (6 байт)
- Тип (2 байта). Содержит информацию о том, на какой вышестоящий уровень передать информацию (IPv4, IPv6, ARP)
- Данные (46-1500 байт). Данные от протокола вышестоящего уровня
- Контрольная сумма (4 байта)

Задачи, решаемые на канальном уровне:
- потеря информации на физическом уровне - обнаружение и справление ошибок
- "затопление" - медленный получатель, быстрый отправитель

Технологии канального уровня:
- Ethernet
- Wi-Fi
- 5G/4G/3G

**MAC - Подуровень управления доступом к среде (media access control)**
MAC адреса используются на канальном уровне для определения какому устройству предназначены данные. Используются в сетях Ethernet и WiFi. Являются **локальными адресами**

Основное сетевое оборудование - **коммутатор, точка доступа**.

Коммутатор служит для объединения нескольких устройств с уникальными MAC адресами в общую локальную сеть. Коммутатор из заголовка фрейма получает адрес получателя и отправляет фрейм на устройство с этим адресом. 

Устройство хранит у себя таблицу маршрутизаци для пересылки фрейма. Если устройство не найдено в таблице маршрутизации, то фрейм **рассылается на все порты** коммутатора, и тогда если коммутатор соединен с другим коммутатором, на него придет фрейм и следующий коммутатор будет искать получателя с этим адресом.

## Сетевой уровень

**Основная задача уровня**: объединить сети, построенные на разных технологиях канального уровня в глобальную сеть и разрешение маршрутизации устройств в глобальной сети.

**Решаемые проблемы**: технологии канальных уровней обладают разными характеристиками:
- уровень сервиса - ethernet без гарантии доставки, wifi с гарантией доставки
- адресация: разный размер, разная структура (плоская, иерархическая), ethernet - mac, сотовые сети - imei
- разный максимальный размер кадра (MTU)
- разный формат кадра

Кроме этого есть причины, по которым нельзя физически создать глобальную сеть на канальном уровне:
- масштабируемость ethernet - на канальном уровне невозможно реализовать глобальную сеть. Таблица марштуризации должна будет содержать адреса всех хостов в глобальной сети. При этом отправлять фрейм на все порты нельзя, тк сеть будет быстро замусорена такими фреймами
- Ethernet сети строятся не закольцованными, чтобы не возникало "широковещательного шторма". Таким образом путь для фрейма будет только один - отсутсвие дублирующих путей между коммутаторами

Единица данных - **пакет**

Основное оборудование которое работает на сетевом уровне - **маршрутизатор**. Маршрутизаторы используются для объединения нескольких сетей.

**Маршрутизация** - поиск маршрута доставки пакета между сетями через транзитные узлы (**маршрутизаторы**).

Основные протоколы сетевого уровня - **[[IP]]** для передачи данных, **ICMP**, **DHCP** и **ARP** - управляющие протоколы обеспечивающие работу сети.

**DHCP** (Dynamic Host Configuration Protocol) - позволяет динамически назначать хостам в сети IP-адреса
**ARP** (Address Resolution Protocol) - обеспечивает связь сетевого и канального уровней, позволят по IP-адресу определить MAC адрес
**ICMP** (Internet Control Message Protocol) - сообщение об ошибках в работе сети

3 уровня - Физический уровень, Канальный уровень, Сетевой уровень реализуются на **сетевом оборудовании**.
Последующие уровни реализуются на хостах (устройства на которых выполняются пользовательские программы)

## Транспортный уровень

**Задачи транспортного уровня:**
- Передача данных между процессами на хостах
- Адресация
- Обеспечение нужного уровня надежности независимого от надежности сети

Единица данных - **сегмент/дейтаграмма**

2 хоста взаимодействуют друг с другом на транспортном уровне - **сквозное соединение** (между двумя хостами может находится любое количество сетевых устройств, транспортный уровень скрывает детали сетевого взаимодействия). Поэтому этот уровень называют сетенезависимым

Для адресации на транспортном уровне используются **порты** - число от 1 до 6553. Каждое сетевое приложение на хосте имеет свой порт.

**Типы портов:**
- Хорошо известные порты (1-1024): с ними работают популярные протоколы/приложения в интернете - 80/443 (HTTP/S), 25 (SMTP), 53 (DNS), 21 (FTP) и тд
- Зарегистрированные порты (1025-49151). Регистрация в Internet Assigned Numbers Authority (IANA)
- Динамические порты (49151 - 65535). Назначаются сетевым клиентским приложениям операционной системой автоматически

Протоколы [[TCP & UDP]]:
- **TCP** - обеспечивает гарантию доставки пакета и порядка следования сообщений
- **UDP** - не гарантирует доставку данных, но работает быстрее TCP. Подходит для стриминга, видео и аудио потоков

Для взаимодействия с транспортным уровнем приложения используют интерфейс сокетов - [[Socket]]. 

## Прикладной уровень
Прикладной уровень в модели TCP/IP объединяет уровни: прикладной, сеансовый и уровень представления из модели OSI. В модели TCP/IP подразумевается что эти уровни должны реализовываться на уровне приложения.

Единица данных - **сообщение**

Протоколы:
- HTTP
- SMTP, IMAP, POP3
- DNS
- FTP

**Пример сеансового уровня:**
При загрузке интернет страницы может потребоваться загрузить стили, скрипты и еще какие-то ресурсы. В протоколе HTTP 1.0 приходилось открывать отдельное TCP соединение на каждый запрос. В HTTP 1.1 добавилась возможность открывать persistent TCP connection (HTTP keep-alive) и стало возможным загружать все ресурсы интернет страницы в рамках одного TCP соединения (сеанс). (но в реальной жизни браузеру приходится открывать ~6 соединений для быстрой загрузки ресурсов - **HOL blocking**)

**Пример уровня представления**
Протокол HTTP может использовать шифрование SSL/TLS. В модели OSI эта функция расположилась бы на уровне представления
