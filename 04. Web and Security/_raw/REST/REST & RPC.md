# REST & RPC

REST & RPC - два основных типа API.

**REST** (**Re**presentational**S**tate**T**ransfer) - клиент и сервер не имеют общего состояния, т.е. сервер не знает ничего о состоянии клиента. Взаимодействие происходит по протоколу HTTP 1.1. Данные для запроса передаются в GET или POST параметрах

**RPC** (Remote Procedure Call) - тип API в котором взаимодействие клиента и сервера выполенно в виде вызова процедур на стороне сервера. При этом некоторые протоколы позволяют передавать потоковые данные (gRPC), возможно двухстороннее взаимодействие, т.е. сервер может отправлять данные клиенту (gRPC, WebSocket).


## REST (Representational State Transfer)

Отличительные черты:
- Протокол взаимодействия - HTTP 1.1
- Взаимодействие "запрос-ответ"
- Не имеет четкой спецификации. Обмен информацией идет в текстовом виде.
- Понятие "ресурс", организация "дерева" ресурсов, и способ взаимодействия с ним (HTTP глаголы).
- Подходит для открытых клиентских API, для API для фронтенда
- Обычно хорошо кешируется
- Человекочитаем

Основные стандарты:
- RESTful API - нестрогий стандрат с общими рекомендации
- json:api - более строгий стандарт чем RESTful API, но не распростанен широко
- GraphQL

#### RESTful API

API сервис предоставляет доступ к "ресурсам" (сущности с которыми позволяет взаимодействовать API) расположенным по определенным URI. Клиент вызывает эти URL с использованием HTTP глагола. Параметры передаются либо в строке запроса (GET) либо в теле запроса (POST), обычно в теле запроса передают json строку в "свободном" формате.

Примеры ресурсов:
- `GET api/v2/user/42` - Получить данные ресурса user с id = 42
- `POST api/v2/user/42` - В теле запроса может быть json, html form или что угодно еще 
- `GET api/v2/users` - Получить список пользователей
