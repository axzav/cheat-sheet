# HTTP/HTTPS

Протокол прикладного уровня. Основной протокол использующийся в интернете для передачи данных. Работает поверх TCP (QUIC). Работает в режиме запрос-ответ, не хранит состояние между запросами.

## Версии HTTP

### HTTP/0.9
Первый стандарт, не было заголовков и статусов.
Поддерживался только метод **GET**

### HTTP/1.0
- Добавлены заголовки
- Коды статусов
- Методы `GET`,`HEAD`и`POST`

### HTTP/1.1

- Виртуальные хосты (заголовок Host)
- Поддержка **постоянных соединений** (Connection: Keep-Alive)
- Поддержка кеширования и сжатия
- Методы `GET`,`POST`,`PUT`,`DELETE`,`HEAD`,`OPTIONS`,`TRACE`, `PATCH`, `CONNECT`
- Base authentication

Т.к. на веб странице существует множество дополнительных ресурсов для загрузки (js, css, images), то для загрузки каждого из них приходилось создавать отдельное HTTP соединение. В версии 1.1 добавили поддержку **постоянных соединений**, что позволило загружать все ресурсы одной страницы в рамках одного TCP соединения без необходимости трехкратного рукопожатия на каждый ресурс.

На практике существует проблема **head-of-line blocking**, когда медленный или большой по размеру ресурс задерживает всю очередь загрузки. 
Протокол HTTP/1.1 в рамках одного подключения способен передавать ресурсы только по очереди и не поддерживает **мультиплексирование**

Поэтому браузеры открывают несколько соединений для загрузки ресурсов страницы (обычно около 6). Постоянные соединения автоматически закрываются через 3-15 секунд сервером


### HTTP/2
https://habr.com/ru/company/selectel/blog/532868/

Стандарт нацелен на более эффективное использование сетевых ресурсов.
Является **бинарным** протоколом в отличие от предыдущей версии.
HTTP запрос разбивается на **фреймы**.
Фреймы отправляются в рамках **стримов**. 

На загрузку одного веб-документа с ресурсами создается **одно TCP соединение** с **несколькими стримами**.

Использование фреймов позволяет мультиплексировать несколько ресурсов внутри одного подключения. Т.е. пересылка фреймов ресусов от сервера может быть не последовательной в рамках одного соединения как это было в HTTP 1.1, а можно отправлять ресурсы частями в разном порядке

**Server Push** - в отличие от предыдущей версии теперь сервер может отправлять данные клиенту. Предполагаемое использование - браузер делает запрос на получение веб страницы, а сервер сразу же возвращает дополнительные ресурсы веб страницы (css, js, images) не дожидаясь запроса на их загрузку


### HTTP/3
Протокол HTTP/2 работает поверх TCP, поэтому проблема **HOL blocking** сохраняется на уровне TCP, хоть и решена на уровне HTTP.

Для решения этой проблемы был разработан новый протокол **QUIC**, который работает поверх UDP. Этот протокол сам обеспечивает мультиплексирование.


## Структура HTTP request/response

**HTTP request**:
```
POST /cgi-bin/process.cgi HTTP/1.1
Host: www.tutorialspoint.com
User-Agent: Mozilla/4.0 (compatible; MSIE5.01; Windows NT)
Content-Type: application/x-www-form-urlencoded
Content-Length: length
Accept-Language: en-us
Accept-Encoding: gzip, deflate
Connection: Keep-Alive

licenseID=string&content=string&/paramsXML=string
```

- `POST` - метод HTTP запроса
- ``/cgi-bin/process.cgi` - URI к которому направлен запрос
- `HTTP/1.1` - версия протокола
- `Host: www.tutorialspoint.com` - обязательный заголовок начиная с HTTP 1.1
- `Connection: Keep-Alive` - начиная с HTTP 1.1 все соединения по умолчанию постоянные и этот заголовок необязателен
- `licenseID=string&content=string&/paramsXML=string` - тело запроса

**HTTP response**:
```
HTTP/1.1 200 OK
Date: Mon, 27 Jul 2009 12:28:53 GMT
Server: Apache/2.2.14 (Win32)
Last-Modified: Wed, 22 Jul 2009 19:15:56 GMT
Content-Length: 88
Content-Type: text/html
Connection: Closed
 
<html>
<body>
<h1>Hello, World!</h1>
</body>
</html>
```

## Методы HTTP

Метод|Описание
:---|:---
GET|Получить содержимое указанного ресурса
POST|Используется для передачи пользовательских данных ресурсу
HEAD|Как метод GET, но без тела в ответе. Служит для проверки наличия ресурса и для извлечения метаданных (получение размера страницы перед ее загрузкой)
PUT|Используется для создания (размещения) новых ресурсов на сервере.
PATCH|Позволяет внести частичные изменения в указанный ресурс по указанному расположению
DELETE|Удаляет указанный ресурс
TRACE|
OPTIONS|Используется для описания параметров коммуникации между клиентом и сервером. Используется браузером для preflight запросов (например CORS)
CONNECT|Преобразует соединение запроса в прозрачный TCP/IP-туннель.

Код|Описание

5XX|Ошибка сервера (502 Bad Gateway, 504 Gateway Timeout)

## URL, URI, URN

- **URL** - Uniform Resource Locator (унифицированный **определитель местонахождения** ресурса)  
- **URI** - Uniform Resource Identifier (унифицированный **идентификатор** ресурса)
- **URN** - Unifrorm Resource Name (унифицированное **имя** ресурса)
