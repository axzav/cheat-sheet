# Coupling и cohesion

Coupling и cohesion (сцепление и связность) — это два важных концепта в ООП и программной инженерии, которые касаются структуры и организации кода. Они помогают определить, насколько хорошо разделены и насколько тесно связаны различные части системы. Давайте рассмотрим эти концепты подробнее.

## Coupling (Сцепление)

Описывает степень зависимости между модулями или компонентами системы. Сильное сцепление означает, что модули сильно зависят друг от друга, в то время как слабое сцепление указывает на минимальные зависимости.

Типы

1️⃣Content Coupling: Один модуль напрямую изменяет или зависит от внутреннего состояния или логики другого модуля.
2️⃣Common Coupling: Модули разделяют общие глобальные данные.
3️⃣Control Coupling: Один модуль управляет потоком управления другого модуля.
4️⃣Stamp Coupling (Data-Structured Coupling): Модули разделяют сложные структуры данных, но используют только часть этих данных.
5️⃣Data Coupling: Модули разделяют простые данные через параметры (наиболее желательное сцепление).

Сильное сцепление (нежелательное):
```java
class ClassA {
    void methodA(ClassB b) {
        b.methodB();
    }
}

class ClassB {
    void methodB() {
        // some logic
    }
}
```

Слабое сцепление (желательное):
```java
interface Service {
    void execute();
}

class ServiceA implements Service {
    public void execute() {
        // implementation
    }
}

class ClassA {
    private Service service;

    ClassA(Service service) {
        this.service = service;
    }

    void methodA() {
        service.execute();
    }
}
```

## Cohesion (Связность)

Описывает, насколько хорошо элементы внутри одного модуля или компонента работают вместе для выполнения одной задачи. Высокая связность означает, что все элементы модуля тесно связаны и работают вместе для достижения одной цели.

Типы 

1️⃣Coincidental Cohesion: Элементы модуля случайно собраны вместе (наименее желательное).
2️⃣Logical Cohesion: Элементы выполняют схожие задачи, но разные по своей природе.
3️⃣Temporal Cohesion: Элементы выполняются вместе, потому что они связаны по времени.
4️⃣Procedural Cohesion: Элементы модуля следуют определённой процедуре.
5️⃣Communicational Cohesion: Элементы модуля работают над одним и тем же набором данных.
6️⃣Sequential Cohesion: Выходные данные одного элемента становятся входными данными другого.
7️⃣Functional Cohesion: Все элементы модуля работают вместе для выполнения одной функции (наиболее желательное).

Низкая связность:
```java
class LowCohesion {
    void step1() {
        // logic for step 1
    }

    void step2() {
        // logic for step 2
    }

    void unrelatedMethod() {
        // unrelated logic
    }
}
```

Высокая связность:
```java
class HighCohesion {
    void performTask() {
        step1();
        step2();
    }

    private void step1() {
        // logic for step 1
    }

    private void step2() {
        // logic for step 2
    }
}
```

Взаимосвязь

✅Желательное состояние: Высокая связность внутри модулей и слабое сцепление между модулями.
✅Причина: Высокая связность упрощает понимание и изменение модулей, так как все элементы модуля тесно связаны и работают над одной задачей. Слабое сцепление уменьшает зависимости между модулями, что делает систему более гибкой и легче поддающейся изменениям и тестированию.

✅Сцепление (Coupling): Степень зависимости между модулями. Желательно минимизировать (слабое сцепление).
✅Связность (Cohesion): Степень, в которой элементы модуля работают вместе для выполнения одной задачи. Желательно максимизировать (высокая связность).

Поддержание слабого сцепления и высокой связности делает систему более гибкой, легкой в поддержке и тестировании.
